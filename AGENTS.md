# AGENTS.md

## Learnings

- Skia (`@shopify/react-native-skia`) cannot decode HEIC, the default capture format on iPhone. Always re-encode picked photos to JPEG (via `expo-image-manipulator`) before handing the URI to `useImage`/Skia, or real device photos will silently fail to render.
- `expo-image-manipulator`'s API changed in SDK 57: the old `manipulateAsync(uri, actions, options)` is deprecated. Use the chainable context API instead: `ImageManipulator.manipulate(uri)...renderAsync()` → `ImageRef.saveAsync(options)`. Check the package's own `.d.ts` files rather than assume the old signature still works.
- `expo-media-library` (SDK 57) moved to a new API: the classic top-level functions like `saveToLibraryAsync` still type-check but throw at runtime. Save with `MediaLibrary.Asset.create(uri)`, and call `requestPermissionsAsync(true, ["photo"])` first — on iOS `Asset.create` only checks write permission, it never prompts for it.
- `useImage()` fails silently — a decode error just resolves to `null` with no thrown error or console output. Its `onError` only covers decoding: when reading the file fails (a missing file, a revoked blob URL), the load promise rejects unhandled and `onError` never runs. Load image layers with `decodeImage` from `layers/decodedImages.ts`, which rejects on both, through its shared `decodedImages` cache, so the editor and export hold one copy of each image.
- A flex container with `alignItems`/`justifyContent: "center"` collapses a `flex: 1` child's cross-axis size to 0 (no stretch). Don't wrap a Skia `<Canvas>` (or anything else that needs `onLayout` to report real dimensions) in a centering container — let it stretch and center its own contents instead.
- `flex: 0` differs on web. In Yoga it means "natural size, don't flex", but React Native Web passes it through as CSS `flex: 0` (`0 1 0%`), so the view starts at zero height and shrinks, and its content spills over its neighbors. To stop a view flexing, leave `flex` off (Views default to `flexBasis: auto; flexShrink: 0` on both) and add `flex: 1` only in the case that should fill.
- In Expo Go, opening `exp://127.0.0.1:8081` while the app is already foregrounded just refocuses it — it does not fetch a fresh JS bundle after installing new dependencies. Force a real reload with `xcrun simctl terminate <udid> host.exp.Exponent` then reopen the `exp://` URL.
- The iOS Simulator MCP tool's taps can silently go nowhere after repeated terminate/reload cycles — the RN JS thread can hang while the simulator itself stays fully responsive. If a tap at coordinates that worked before suddenly does nothing, don't assume your coordinate math is wrong: press the hardware HOME button first. If HOME works instantly but in-app taps still do nothing, the JS thread is hung — do a real `simctl terminate` + relaunch, not just another `open_url`/foreground refocus. Also give buttons real `hitSlop` (RN's default is the raw layout box, no forgiveness); it fixes real touch-target UX and takes tap-coordinate guessing out of your own testing.
- The root `SafeAreaView` leaves out the bottom edge, so bars and sheets can reach under the home indicator. Each screen or full-screen overlay pads its own bottom content with `useSafeAreaInsets().bottom`, added to its usual padding; a new one must too. Don't push a view past a padded parent with a negative offset instead: the screen container clips it.
- `TextInput`'s `selectTextOnFocus` doesn't apply when focus comes from `autoFocus` on iOS. Select from `onFocus` with `ref.setSelection(0, length)` instead, which covers both tap and autofocus.
- The iOS simulator here runs headless (no Simulator.app), with a hardware keyboard attached, so the software keyboard never appears and keyboard-overlap bugs can't be reproduced on it. Verify keyboard layout on a real device.
- A flaky `expo start --tunnel` can leave the app running a stale or half-updated bundle with no error in the app: a button from the new code can call a handler the old code never wired up. If behavior contradicts the code, check the Metro output for "Tunnel connection has been closed" before debugging, and prefer LAN mode (`npx expo start`) for simulator work.
- `npm install` copies `package.json`'s indentation into `package-lock.json`, and `npx expo install` rewrites `package.json` with 2 spaces (and `app.json` too when it adds a config plugin; run `npm run format` to restore its tabs). Biome is set to format both files with 2 spaces to match; if a dependency change shows a lockfile diff in the thousands of lines, check `git diff -w` before committing — it's indentation, not content.
- On web, Skia's module binds to CanvasKit the moment it's first evaluated (`Skia = JsiSkApi(global.CanvasKit)`), and Expo Router evaluates every route at startup. Anything that imports Skia before CanvasKit loads gets a dead API, whose factories throw `Cannot read properties of undefined` only when first called. That's why `index.web.ts` loads CanvasKit and only then dynamically imports `expo-router/entry`. It must import `expo` first, because Expo's runtime installs the loader Metro's dynamic `import()` needs on web.
- Skia paragraphs on web throw without an `SkTypefaceFontProvider` (CanvasKit has no system fonts). Build every paragraph with `getFontProvider()` from `layers/fonts.ts`.
- On web, `Pressable` fires `onPress` from the DOM `click`, which bubbles from any child, including a `TextInput` that natively would take the touch itself. Don't wrap an input in a tap-to-dismiss `Pressable`: put an `absoluteFill` `Pressable` behind it as a sibling, and give the input `position: "relative"`. RNW leaves the `<textarea>` static, and CSS paints static elements under positioned ones, whatever the DOM order.
- React Native Web's `Alert.alert` is a no-op. Use `showAlert` from `ui/`. A plain `Alert` inside `usePreventRemove` blocks navigation on web with no way out.
- To test the photo picker in the browser pane, don't patch `input.click()` or wait for the input with a `MutationObserver`: `expo-image-picker` appends its `<input type=file>` and dispatches a synthetic click in the same synchronous step, so an observer runs too late and the pane cancels the real file dialog. Listen on `window` in the capture phase instead. On the input's `click`, `preventDefault`, set `files`, and dispatch `change` from a `setTimeout`. Stop the input's `cancel` from propagating, or the picker's handler runs twice and throws a `removeChild` error.
- A gesture-handler `Pan` with `minDistance(0)` activates at touch-down on web, but on iOS only once the finger moves, so a tap there never reaches `onEnd`. To act on a tap too (the paint gesture's dot), commit from `onFinalize`, and cancel on a second finger yourself (`numberOfPointers`, `onTouchesDown`) rather than with `maxPointers`, whose failure looks the same as a tap's.
- To drag a gesture-handler gesture in the browser pane, use the `computer` tool's `left_click_drag`. Synthetic `PointerEvent`s dispatched from JavaScript don't work: RNGH calls `setPointerCapture`, which throws for a pointer the browser didn't create, and every move raises another error overlay. `left_click_drag` sends a single move, though, and a Pan counts translation from where it activates (on web and iOS alike), so a Pan with an `activeOffset` sees no translation at all. Drive those with several `Input.dispatchMouseEvent` moves in headless Chrome over CDP.
- The worklets Babel plugin turns each `"worklet"` function declaration into a constant that captures the helpers it calls when it's defined, so it isn't hoisted. A worklet that calls a function declared further down the file throws "Cannot access 'x' before initialization" as the module loads (on web, a server error on every page). Declare helpers above the worklets that use them.
- On web, Skia can drop redraws asked for while its canvas surface is still being set up. A scene whose only changes after mounting come from shared values (an opening animation, say) can stay blank until something else redraws it. Mount the drawing once the view has a size, as `EditorCanvas` and `CropCanvas` do.
- Geometry that gestures need on the UI thread (in `model/geometry.ts`, `model/drawing.ts`'s hit testing, `layers/layerTransform.ts`, `features/editor/viewport.ts`, `features/editor/handles/handleGeometry.ts`, `features/editor/handles/handleMetrics.ts`, `features/editor/crop/cropGeometry.ts`, `features/editor/crop/cropDrag.ts`, `features/editor/canvas/hitTest.ts`, `features/editor/canvas/snapping.ts`) is marked `"worklet"`. A worklet can only call other worklets, so a new helper called from one needs the directive too. It's just a string, so `model/` stays free of React Native.
- `scheduleOnUI` on web runs its worklet a frame later (a microtask, then `requestAnimationFrame`), while a shared value written from JS there changes at once. Where that frame matters, call the worklet directly on web, as `syncLiveTransform` does. On native, a JS write is scheduled on the UI thread anyway, so a worklet that must read and write shared values atomically (say, to check what a gesture holds) belongs in `scheduleOnUI`.
- `expo-file-system` (SDK 57) has no web implementation: `File` and `Directory` are empty stubs there. Anything stored with it on native needs its own `.web.ts` (projects use IndexedDB). On native, `move` and `copy` are async; `moveSync`/`copySync` are the synchronous versions.
- The iOS Simulator tool's `text` action returns before the app has handled the keystrokes, so a tap right after it (say, on Done) can reach JS before the text does and act on an empty input. Screenshot to confirm the text landed before tapping.
- The iOS Simulator tool's `screenshot` can return a frame from before the last tap or touch path took effect. Before deciding a tap did nothing, or that something stayed on screen after a gesture ended, take a second screenshot.
- React Native's style types don't allow web-only CSS values (`cursor: "nwse-resize"`, `outlineStyle: "none"`), so those need an `as unknown as ViewStyle`/`TextStyle` cast. Keep it inside a `Platform.OS === "web"` branch.
- Metro prefers a platform file only over a file with the same extension: it tries `.web.ts`, `.ts`, `.web.tsx`, `.tsx` in turn, so `foo.ts` silently wins over `foo.web.tsx`. Give a `.web` file and its native counterpart the same extension (`ui/showAlert.tsx` is `.tsx` for this, though it has no JSX). When web runs native code, check which file the bundle names before debugging the code. A `.web` file can import only types from its counterpart (`./GlassView`): on web that path resolves back to the `.web` file itself, so a value imported from it is undefined.
- React Native Web's `Pressable` passes `hovered` to its `style` and `children` callbacks, though React Native's types only declare `pressed`. Read it with `interaction()` from `ui/interaction.ts` (it's always false on native), and ease the change with `webTransition` from `theme.ts`. For hover over a group, such as a card and a delete button beside it, put `onPointerEnter`/`onPointerLeave` on a wrapping view and only count `pointerType === "mouse"`, or a touch reads as a hover.
- On web, Reanimated renders an `Animated.View`'s style inline, so `pointerEvents: "box-none"` there is silently dropped (RNW implements it with a class), and the view swallows every click in its bounds. Put `box-none` on a plain `View` around it. To animate such an overlay out, keep that plain View mounted and toggle only the animated child, as `LayersPanel` does.
- React Native Web's `Image` calls `onLoad` with the DOM load event, which has no `nativeEvent.source`. Read an image's size with `Image.getSize`, which works on both.
- Tests import the module under test with an explicit `.ts` extension and start with `/// <reference types="node" />`: Node's type stripping needs the extension, and TypeScript 6 no longer includes installed `@types` packages by default. Node can't resolve the `@/` alias or load React, so a tested module imports its dependencies by relative `.ts` path and nothing React-based at runtime. Store slices follow this: they import only types from `store/index.ts`, and tests build a vanilla store with `createStore` from `zustand/vanilla`.

## Project Structure

- Keep imports flowing one way: `app` → `features` → `import` / `render` / `projects` / `layers` / `store` → `model`. Route files only register screens; feature screens compose shared capabilities (the home screen hands `renderThumbnail` from `render/` to `closeProject`). Features don't import other features. `model/` stays plain TypeScript (no React, React Native, or Skia); `ui/` and `theme.ts` never import feature or route code, and `lib/` imports only itself. Update the `noRestrictedImports` overrides in `biome.json` when boundaries change.
- `features/home/`, `features/create/`, `features/editor/`, and `features/export/` own their screen implementations and screen-specific UI. Export options, saving, sharing, and the render hook belong to `features/export/`; document rendering shared by export and home lives in `render/`. Shared photo import and project storage remain in `import/` and `projects/`; reusable controls live in `ui/`.
- `model/` is the document and the geometry it's built from. Pure logic that only the editor uses (`viewport.ts`, `handles/handleGeometry.ts`) lives in `features/editor/`, with its test beside it.
- `features/editor/` has a subfolder per part of the editor: `canvas/` (drawing and transforming layers), a folder per tool (`crop/`, `text/`, `draw/`: its full-screen editor or bottom panel and its settings), `panels/` (the toolbar, layer actions, and the layers panel), and `handles/` (selection handle geometry, touch metrics, and cursors, which the canvas and crop share). Other subfolders don't import each other: what two of them share, like `viewport.ts`, `ToolButton`, or `ColorSwatches`, lives at the editor root. The root helpers don't import subfolders; `EditorScreen.tsx` composes them. Editor-wide pieces such as keyboard shortcuts and adding photos live at the root too.
- `store/` holds only state shared across screens, as Zustand slices combined in `store/index.ts`; state local to one screen stays in `useState`. `layers/` takes plain props and never reads the store, so export can render any document. Select the narrowest value a component needs.
- Only routes go in `src/app/` — expo-router turns every file there into a screen. Keep screen implementations in `src/features/`.
- Name component files in PascalCase and other modules in camelCase. Prefer growing an existing file over adding a single-use one; split a file when it gains a second responsibility.
- Name the editor document `document` (not `doc`). TypeScript's DOM lib declares a global `document`, so a missing parameter or destructure still type-checks against the browser global; watch for that when renaming.

## Git Commits

- Use Conventional Commits format for commit messages, such as `feat: add text editing` or `fix: handle invalid image input`.

## Code Checks

- After code changes, run `npm run check` to verify formatting and linting, `npm run typecheck` for TypeScript, and `npm test` when touching `model/`, store slices, or other pure modules. Run `npm run build:web` after changing platform files (`.web.ts`), the entry files, or imports TypeScript doesn't check (assets, untyped imports): it bundles with Metro, which catches an import that won't resolve. It doesn't run the app, since the static export renders only an empty shell. CI runs all four. Use `npm run format` to apply formatting fixes, and run `npm run lint` when checking lint rules only.
