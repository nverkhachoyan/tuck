# AGENTS.md

## Learnings

- Skia (`@shopify/react-native-skia`) cannot decode HEIC, the default capture format on iPhone. Always re-encode picked photos to JPEG (via `expo-image-manipulator`) before handing the URI to `useImage`/Skia, or real device photos will silently fail to render.
- `expo-image-manipulator`'s API changed in SDK 57: the old `manipulateAsync(uri, actions, options)` is deprecated. Use the chainable context API instead: `ImageManipulator.manipulate(uri)...renderAsync()` → `ImageRef.saveAsync(options)`. Check the package's own `.d.ts` files rather than assume the old signature still works.
- `expo-media-library` (SDK 57) moved to a new API: the classic top-level functions like `saveToLibraryAsync` still type-check but throw at runtime. Save with `MediaLibrary.Asset.create(uri)`, and call `requestPermissionsAsync(true, ["photo"])` first — on iOS `Asset.create` only checks write permission, it never prompts for it.
- `useImage()` fails silently — a decode error just resolves to `null` with no thrown error or console output. Its `onError` only covers decoding: when reading the file fails (a missing file, a revoked blob URL), the load promise rejects unhandled and `onError` never runs. Load image layers with `decodeImage` from `render/decodedImages.ts`, which rejects on both, through its shared `decodedImages` cache, so the editor and export hold one copy of each image.
- A hook holding an image from `decodedImages` must forget it in the same cleanup that releases it: the cache frees a released image a moment later, and a URI that goes away and comes back (a mask taken off, then put back) would otherwise hand the freed image to Skia, which throws "Cannot pass deleted object as a pointer of type Image const*" on web. `useDecodedImage` keeps holding the image it shows until the next one has decoded, and releases it only in the step that swaps its state (a `uri` gone to null swaps to nothing at once). Anything that keeps an image past its holder (a recorded `SkPicture` keeps its pixels) should be cached by the decoded image, as `maskedRedactionPicture` does, so it goes with it. The cache also waits two animation frames before freeing: on web a Skia canvas can still draw the scene recorded before React let go of an image until the next frame (its redraw and its animation mapper's stop both wait for one), and a replay of that recording throws the same error from deep in CanvasKit's `Array.forEach`.
- A flex container with `alignItems`/`justifyContent: "center"` collapses a `flex: 1` child's cross-axis size to 0 (no stretch). Don't wrap a Skia `<Canvas>` (or anything else that needs `onLayout` to report real dimensions) in a centering container — let it stretch and center its own contents instead.
- `flex: 0` differs on web. In Yoga it means "natural size, don't flex", but React Native Web passes it through as CSS `flex: 0` (`0 1 0%`), so the view starts at zero height and shrinks, and its content spills over its neighbors. To stop a view flexing, leave `flex` off (Views default to `flexBasis: auto; flexShrink: 0` on both) and add `flex: 1` only in the case that should fill.
- A `flex: N` view inside a column whose height comes from its content collapses to zero height on native (Yoga starts it from `flexBasis: 0` with nothing to grow into) but keeps its content's height on web, where React Native Web's `0%` basis falls back to auto. Home's secondary start buttons spilled under the home indicator on iOS this way. Give a view `flex` only where its parent has a size to share. The wide editor's Adjust section is the same case: `AdjustPanel` is `flex: 1` for the phone dock's fixed slot, so the inspector leaves `flex` off and the section's height follows the heading, chips, and dial (`AdjustInspector`), while the layers take the rest.
- A wide window (1024 points and up, web and iPad) puts the open tool in the header's context bar (`shell/ContextBar`) and the tools in the rail. Crop's options sit in that bar too, with the straighten dial in a strip under the photo, and Stickers opens beside the rail. The layers inspector stays open when the window is at least 960 points tall (`editorFrame`). A shorter window, such as a 13-inch laptop's browser, leaves that width for the photo until Layers, Find, or Adjust opens the panel. A fine pointer, whatever the window's size, gets controls sized for a mouse (`compactControls` from `ui/density.ts`): a 48-point header, a narrower rail with smaller tools, 36-point bar options, and tighter gaps and corners around the cards. It's read once as the page loads, like the palette, so each size is a constant chosen when its module loads (`HEADER_HEIGHT`, `PANEL_GAP`, `RAIL_WIDTH`). An iPad reports a coarse pointer even with a trackpad, so only a web browser on a computer changes. Phones keep the dock and its trays. `optionsOpen` is only the phone's tray; the wide layout never reads it. A popover's open state belongs to its chip. Find's Faces, Text, and Both, and Adjust's dial, are inspector sections above the layers, because they need the column's height. `modeChrome` (`editorChrome.ts`) chooses the panel, its title, and what ✕ and ✓ do, once for both layouts, and whether the panel sits in the bar (on a wide window, every panel but `"idle"`). The bar's ✕ and ✓ are `ModeActions`, shared with the dock's footer, which only draws them. What each panel shows comes from one table, `TOOL_VIEWS` (`EditorDock.tsx`), whose entry holds its dock panel, bar, tray, and inspector section. So the two layouts can't disagree about which one shows, what it does, or which tools they offer.
- The context bar's options are groups (`BarSections`). Items in a group sit 2 points apart. Between groups, a 1-point rule in `colors.borderStrong`, 24 tall, with 10 points on each side. The highlighter marks the mode only. A value is a `BarChip` (a glyph, its words, and a caret) opening a popover; a color stays a swatch, with a word when several sit together (`ColorChip`'s `title`). The row scrolls, and the fade covers from the first option that doesn't fit whole, on the left as well as the right, settling once scrolling stops. `Children.toArray` doesn't enter a component, so a tool returns `BarGroup`s and the bar inserts the rules. A fragment is one child of a group, so the buttons inside it stack in that slot. An `onLayout` x is relative to its parent, not the scrolled viewport. A chip's popover clears that measurement parent, or its choices would count as options in the row. React Native Web ignores `accessibilityState.expanded`, `checked`, and `selected`, so a chip also sets `aria-expanded`, a switch sets `aria-checked`, and a tool sets `aria-selected`. A later style's `undefined` doesn't clear an earlier value, so a titled color chip leaves `width` off rather than setting it to `undefined`.
- `ui/Popover` is modal on web and on native. `placement` is `below` (under the control, or above it near the window's bottom) or `beside` (at the control's right, top-aligned, for a button in the rail). On web it portals to `document.body`, sits under tooltips and alerts, and stops Escape in the window's capture phase, so the editor doesn't also finish the tool. A listener on that same window still runs, so it has to honor `defaultPrevented`. `restoreFocus` runs from the unmount cleanup through a ref: an effect that lists the callback refocuses while the popover is still open, because a new callback identity re-runs it. While text is being typed, a press in the context bar would blur the hidden input; the bar prevents that mousedown's default on web (`keepFocus`), as the canvas does, and the popover's `restoreFocus` returns the caret to the input.
- The app runs in a development build (`expo-dev-client`), not Expo Go, which lacks the local `image-analysis` module and fails at startup. `ios/` and `android/` are generated by `expo prebuild` and ignored by git, so native configuration lives in `app.json` and config plugins. Rebuild with `npx expo run:ios` or `npx expo run:android` after changing `modules/`, `app.json`, or a native dependency (add `npx expo prebuild --clean` first when `app.json` or a plugin changed); JS changes only need Metro.
- To load a fresh bundle in the development build, `xcrun simctl terminate <udid> com.nverk.tuck`, then open `exp+tuck://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A<port>` (on Android, `adb reverse tcp:<port> tcp:<port>` first and `adb shell am start -a android.intent.action.VIEW -d <url>`). Opening that URL with `simctl openurl` or the Simulator tool shows an "Open in Tuck?" prompt that must be tapped. `expo run:ios --no-bundler` won't take `--port` and always opens port 8081, so reopen the URL when Metro runs elsewhere.
- iOS 27 stops an app built with its SDK at launch (`EXC_BREAKPOINT` in `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`) unless it adopts the scene life cycle. The simulators here run iOS 26.5, so only a device shows it. Expo 57's template doesn't adopt it; `plugins/withSceneLifecycle.js` makes the SDK 58 template's changes and can go once the template has them. On a device, launch with `xcrun devicectl device process launch --device <udid> --terminate-existing --payload-url <dev client URL> com.nverk.tuck`, and read crash reports with `xcrun devicectl device info files --domain-type systemCrashLogs`: the app quitting with exit code 0 there can still be a crash.
- The app runs on iPad (`ios.supportsTablet`). An iPad app must allow every orientation and a resizable window, so Expo writes all four orientations to `UISupportedInterfaceOrientations~ipad` while the iPhone stays portrait. iPad shows the wide layouts (the rail and the inspector), so check a layout change on the iPad Pro 13-inch simulator too. The store screenshots come from Release builds: a development build covers the app with its floating Tools button (see `docs/store-listing/listing.md`).
- CocoaPods here (Homebrew Ruby 4) crashes with "Unicode Normalization not appropriate for ASCII-8BIT" unless the locale is UTF-8: run `pod install` and `npx expo run:ios` with `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`.
- Expo's precompiled modules (`ExpoModulesCore` and the others the Podfile links as xcframeworks, since it sets `EXPO_USE_PRECOMPILED_MODULES`) and `expo-modules-jsi`'s xcframework are built by one Swift compiler, and a newer Xcode rejects them ("this SDK is not supported by the compiler", then "cannot find type '__ObjC::expo' in scope"): Xcode 27.1's Swift 6.4 did for Expo 57's 6.3.1. Until Expo ships ones built with it, run `pod install` with `EXPO_USE_PRECOMPILED_MODULES=0`, and rebuild the JSI framework with `PODS_ROOT=$PWD/ios/Pods node_modules/expo-modules-jsi/apple/scripts/build-xcframework.sh --clean` (its build phase caches each slice by its sources, not the compiler, so it keeps the old one).
- The Android SDK is at `~/Library/Android/sdk` but isn't on `PATH`: export `ANDROID_HOME` to it and add its `platform-tools` and `emulator` to `PATH`. The `Medium_Phone_API_36.1` AVD runs a Google Play image, which ML Kit's Play services models need. Play services downloads those models itself, so the emulator needs a network connection once (it has been left in airplane mode: `adb shell cmd connectivity airplane-mode disable`); until then, detection rejects with "still being downloaded".
- ML Kit's `com.google.mlkit.vision.DEPENDENCIES` manifest entry (the models Play services downloads at install) is one comma-separated value, and `expo-dev-launcher` sets it too (`barcode_ui`), so the manifest merger fails if a library declares it. `modules/image-analysis/app.plugin.js` sets it in the app's manifest with `tools:replace`; add a new model to its `MODELS` there, not to the module's `AndroidManifest.xml`.
- Imported photos are already upright: the import's re-encode applies EXIF orientation and writes no orientation tag (checked on iOS and Android; web re-encodes through a canvas). A layer's `width` and `height` are therefore the upright size. `image-analysis` still applies EXIF orientation itself, so its rectangles are in upright pixels for any file.
- Vision and MediaPipe look for faces in the whole image shrunk to a few hundred pixels, so they find none in a 3000-pixel group photo whose faces are 50 pixels wide. `detectFaces` has them look at overlapping tiles too, planned and merged in `modules/image-analysis/src/faceTiles.ts` (tested with `npm test`). ML Kit searches every scale down to its `minFaceSize` itself, so Android gets only the whole image: tiling it found the same faces seven times slower.
- Metro rejects an `import()` with a computed path, even inside `node_modules`, and every build of `@mediapipe/tasks-vision` has one. The web module loads the library's script build (`vision_bundle.js`, which defines a global `Vision`) from `public/mediapipe/` with a `<script>` tag, and imports only its types. Background removal uses version 1 of MagicTouch, which only `InteractiveSegmenterLegacy` runs: the library's new `InteractiveSegmenter` is for version 2's `.task` file. MediaPipe's `detect` fails ("ROI width and height must be > 0") on a canvas resized since the call before; give each tile its own canvas.
- Selecting objects on web runs MobileSAM with `onnxruntime-web` in a module worker that isn't bundled: `modules/image-analysis/src/mobileSamWorker.js` is plain JavaScript, copied to `public/` by `copy-web-assets.mjs` like the runtime and models, so rerun that script after editing it. The runtime's package `exports` none of its `dist/` files (resolve its folder from the package's main file). Its `.bundle` build already holds its WebAssembly glue: give `env.wasm.wasmPaths` the `.wasm` file's URL as `{ wasm }`, since a folder prefix makes it fetch the glue anyway. WebGPU sessions must be created one after another ("another WebGPU EP inference session is being created"), and a session's first run on WebGPU takes about a second to set up, so the worker runs the decoder once after encoding.
- ONNX Runtime's Core ML execution provider only takes nodes whose shapes are fixed: with MobileSAM's encoder still taking any height and width, it split the model into dozens of partitions and ran several times slower than the CPU. The encoder file is fixed at 1024×1024 (`onnxruntime.tools.make_dynamic_shape_fixed`, then `onnxsim`), and every platform pads the image to that square with ImageNet's mean, which the encoder normalizes to zero, as its own padding did: the embeddings come out identical. Core ML also takes at most five dimensions, so TinyViT's six-dimensional window reshapes (whose first dimension is 1) were rewritten to five, leaving one Core ML model instead of 21, each with buffers of its own (a gigabyte of memory between them). Core ML compiles the model when a session first loads it, which takes seconds; `ModelCacheDirectory` keeps the compiled model under the file's `COREML_CACHE_KEY` metadata (otherwise a hash of its path, which changes with every install), so change that key when the model changes. The decoder's output size follows its `orig_im_size` input, so it stays on the CPU. On Android, ONNX Runtime's CPU arena kept half a gigabyte after the encoder ran, so sessions turn it off, and 1.31 ships telemetry, which `ObjectSelector` turns off.
- Hermes has no `Array.prototype.toSorted`: calling it throws "undefined is not a function" on iOS and Android while web works. Sort a copy instead.
- The iOS Simulator MCP tool's taps can silently go nowhere after repeated terminate/reload cycles — the RN JS thread can hang while the simulator itself stays fully responsive. If a tap at coordinates that worked before suddenly does nothing, don't assume your coordinate math is wrong: press the hardware HOME button first. If HOME works instantly but in-app taps still do nothing, the JS thread is hung — do a real `simctl terminate` + relaunch, not just another `open_url`/foreground refocus. Also give buttons real `hitSlop` (RN's default is the raw layout box, no forgiveness); it fixes real touch-target UX and takes tap-coordinate guessing out of your own testing.
- The root `SafeAreaView` leaves out the bottom edge, so bars and sheets can reach under the home indicator. Each screen or full-screen overlay pads its own bottom content with `useSafeAreaInsets().bottom`, added to its usual padding; a new one must too. Don't push a view past a padded parent with a negative offset instead: the screen container clips it.
- `TextInput`'s `selectTextOnFocus` doesn't apply when focus comes from `autoFocus` on iOS. Select from `onFocus` with `ref.setSelection(0, length)` instead, which covers both tap and autofocus.
- On web, React focuses an `autoFocus` element while committing, when its event system is switched off, so `onFocus` never runs for that focus. To act on the first focus (placing the caret), leave `autoFocus` off and call `ref.current.focus()` from a mount effect. React Native Web's `TextInput` ref is the DOM `<textarea>`, which has `setSelectionRange`, not `setSelection`.
- The iOS simulator here runs headless (no Simulator.app), with a hardware keyboard attached, so the software keyboard never appears and keyboard-overlap bugs can't be reproduced on it. Verify keyboard layout on a real device.
- A flaky `expo start --tunnel` can leave the app running a stale or half-updated bundle with no error in the app: a button from the new code can call a handler the old code never wired up. If behavior contradicts the code, check the Metro output for "Tunnel connection has been closed" before debugging, and prefer LAN mode (`npx expo start`) for simulator work.
- `npm install` copies `package.json`'s indentation into `package-lock.json`, and `npx expo install` rewrites `package.json` with 2 spaces (and `app.json` too when it adds a config plugin; run `npm run format` to restore its tabs). Biome is set to format both files with 2 spaces to match; if a dependency change shows a lockfile diff in the thousands of lines, check `git diff -w` before committing — it's indentation, not content.
- On web, Skia's module binds to CanvasKit the moment it's first evaluated (`Skia = JsiSkApi(global.CanvasKit)`), and Expo Router evaluates every route at startup. Anything that imports Skia before CanvasKit loads gets a dead API, whose factories throw `Cannot read properties of undefined` only when first called. That's why `index.web.ts` loads CanvasKit and only then dynamically imports `expo-router/entry`. It must import `expo` first, because Expo's runtime installs the loader Metro's dynamic `import()` needs on web.
- The static export's pages are rendered without hydration: `index.web.ts` sets `__EXPO_ROUTER_HYDRATE__` to false, so the browser renders each page afresh. The server's HTML can't match the client's: it's in the day palette (React keeps the server's class names when hydrating, so a night page came out half day), and the server has no icon font, so every `@expo/vector-icons` icon is empty text there (React error #418). Anything that differs between server and browser is therefore safe to render, but the prerendered HTML is only a placeholder until the bundle and CanvasKit load.
- `vercel.json` sends a Content Security Policy that allows only the site itself (plus `blob:` and `data:`, and `'wasm-unsafe-eval'` for the WebAssembly). Anything new the web app loads or connects to, or a new inline script, needs it changed: `npm run build:web` fails when an inline script's hash is missing from `script-src` (`scripts/check-csp.mjs`), and a blocked request shows as a "Refused to connect" console error. `connect-src 'self'` is also what keeps MediaPipe from sending its usage logs to `odml.pa.googleapis.com`, which it does unconditionally: don't widen it.
- The web app has a service worker, so it opens offline: `build:web` writes `dist/sw.js` from `scripts/service-worker.js` (`scripts/write-service-worker.mjs` adds the version, a hash of the files it precaches, and the list). It precaches the pages, scripts, fonts, icons, and CanvasKit; keeps the detection engines with the version that first used them and stickers from their first use; and serves pages from the network while online. A new version waits until home's "A new version of Tuck is ready" Reload, or every tab closes. Each version's cache holds unhashed files too, so look in `CURRENT` before other versions: `caches.match` alone returns the oldest copy. `index.web.ts` registers it only in a production build. To take it back out, deploy a `sw.js` that unregisters itself (`self.registration.unregister()` on activate); deleting the file leaves installed workers running.
- Photos shared to the installed web app (the manifest's `share_target`) are posted to the service worker, which keeps them in the `tuck-shared` cache and redirects to home's `shared` param; ones opened with it (`file_handlers`) arrive through `window.launchQueue` and are kept there too (`photos/sharedPhoto.web.ts`). Neither can be set off from a page: test the share by submitting a multipart form to `/share-target` from `about:blank` in headless Chrome over CDP (the app's CSP has `form-action 'none'`, and a `fetch` POST follows the redirect to the cached page, hiding it), and a launch by wrapping `LaunchQueue.prototype.setConsumer` with `Page.addScriptToEvaluateOnNewDocument` to hand the consumer a real file handle from `navigator.storage.getDirectory()`. CDP's `Page.getAppManifest` leaves `file_handlers` out even of a valid manifest; only its `errors` say anything about them.
- The `web-export` launch configuration serves `dist/` with `serve` (clean URLs, like Vercel), for checking a `npm run build:web` in the browser pane. `serve` doesn't apply `vercel.json`'s rewrites or headers; to check headers, write them to `dist/serve.json` (`{"headers": [{"source": "**", "headers": [...]}]}`) before starting it, and add `"rewrites"` for `/projects/:id` (to `/projects/[id].html`) and its `/export` for the service worker's precache. `serve` reads it only at startup. The service worker it installs stays registered for that origin: a dev server later started on the same port (the `web` configuration moves to 8083 when 8082 is taken) is served the old export's cached pages and scripts. If the page shows code you've changed, check `navigator.serviceWorker.controller`, then unregister it and delete its caches.
- A Skia backdrop filter (`BackdropFilter`, `BackdropBlur`) reads only the layer it's drawn in, not the whole canvas: inside a `Group layer`, a `Mask`, or anything else that saves a layer, it blurs that layer's empty contents. Redactions work because the editor and export draw layers straight onto the canvas; keep it that way. Skia maps a filter's sigma through the canvas's transform, so a blur in document units looks the same at any zoom, on native and web.
- A highlighter stroke starts a drawing whose `blend` is `"multiply"` (`strokeBlend` in `model/layers/drawing.ts`). `drawStroke` joins the selected drawing only when the stroke blends the same way, so a pen or the see-through marker (`tip: "ink"`, drawn at `MARKER_OPACITY`) stays on its own layer, and an eraser still joins either. `DrawingLayerView` sets that blend on the group's paint and draws the highlighter strokes at full strength. Strokes in one layer composite normally and the group multiplies once, so two highlights darken where they cross only when each is its own layer. The blend has to be that group, and the editor and export draw each document layer straight onto the canvas, so the group multiplies onto the photo. Inside another saved layer it would multiply onto that layer alone. A marker saved before the field has no `blend` and still draws at `MARKER_OPACITY`. On web, CanvasKit accepted `blendMode="multiply"`: over white, `#FFD60A` stayed 255, 214, 10 and black text under it stayed 0, 0, 0; a second layer over the first darkened the overlap to `#FFB400`; over a blue sticker the yellow became dark olive; on a near-black canvas the band disappeared and white text turned the highlight color, which is why the see-through marker remains. The export preview matched those pixels by day and at night (the web editor and export are both sRGB). A neutral gray wasn't compared on the iOS simulator, where a canvas defaults to Display P3 unless `colorSpace="srgb"`.
- React Native Skia's web build throws for runtime-shader, matrix-transform, tile, and picture image filters, and CanvasKit has no runtime image filter at all, so an effect that must run everywhere is built from blur, displacement map, shader, offset, and morphology filters (`pixelateFilter` in `RedactionLayerView.tsx`). A filter's own shader draws in the canvas's color space, which is Display P3 on a `Canvas` left at its default: a red or green in a displacement map bleeds into the other channels there, and only gray (with alpha) passes through unchanged. A displacement map samples its input nearest-neighbor from 8-bit offsets, so a sample point near a pixel edge can flip between neighbors from one pixel to the next.
- Skia works filters and color matrices in the surface's color space. On iOS a `Canvas` defaults to `colorSpace="p3"`, while `drawAsImage` (export, thumbnails, the eyedropper) renders offscreen in sRGB, and the web is sRGB throughout: the same adjustment came out visibly stronger in the editor than in the file it exported. The editor's and crop tool's canvases set `colorSpace="srgb"` for this; a new canvas that previews the document should too. To check which space a filter ran in on the simulator, read a neutral gray from `xcrun simctl io booted screenshot` (sRGB-tagged): grays have the same values in sRGB and P3, so only the filter's own math moves them. A `ColorMatrix`'s last column is in 0–1 units, not 0–255.
- CanvasKit's `readPixels` returns null for `ColorType.Gray_8` from a GPU surface (what `drawAsImage` renders to on web). Read `RGBA_8888` and keep one channel instead; `Skia.Image.MakeImage` with `Gray_8` does work on web, and encodes to an 8-bit grayscale PNG (`cutout/cutMask.tsx` builds masks this way).
- On web, every `drawAsImage` makes a WebGL context of its own, which lasts until it's garbage collected, and a browser keeps only so many: a few quick export renders lost the oldest, the editor's canvas or a reopened sheet's. Draw offscreen with `drawOffscreen` from `render/drawOffscreen.ts`, which is `drawAsImage` on native and one shared surface on web. Don't hand a large `SkImage` that something will dispose to a Skia canvas that must keep up with quick changes either: the export sheet's preview drew its render's image and threw "Cannot pass deleted object" after quick size changes however long the disposal waited, so it shows a small PNG data URL copy in a React Native `Image` instead.
- On web, a closing screen that's opened again before navigation lets go of it can come back with its state but after its effects were cleaned up, so anything a cleanup freed is still in state. `useRenderedDocument` remembers that it was cleaned up and shows nothing it held until its effects run again.
- On web, a `BottomSheet` whose content is taller than its slot shrinks it, and the shrinking fights the sheet's entering slide (`SlideInDown` came to rest hundreds of points low). Size a sheet's content to fit in JavaScript instead, as the export sheet's preview strip does.
- `inert` takes a subtree out of the Tab order and the accessibility tree on web, but React Native Web doesn't pass the prop through: set it on the element from a ref (the editor does, while the export sheet is over it). On iOS, the sheet's container sets `accessibilityViewIsModal`.
- The declarative API can't draw into a backdrop layer (`BackdropFilter`'s children draw after it's restored), so `RedactionLayerView` records an `SkPicture` that calls `saveLayer` with a backdrop itself; playback keeps it. Give `beginRecording` explicit bounds: on web it defaults to a rect from (0, 0), which culls anything drawn left of or above the origin.
- A Skia `Group`'s `opacity` doesn't fade a paragraph, which draws with its own paints: text inside comes out at full strength. Fade it through a layer instead, `<Group layer={<Paint opacity={…} />}>`, as the text placeholder in `EditedTextView` does.
- Skia paragraphs on web throw without an `SkTypefaceFontProvider` (CanvasKit has no system fonts). Build every paragraph with `getFontProvider()` from `render/fonts.ts`.
- Text is edited in place: the canvas draws the draft layer, its caret, and its selection with Skia, and `TextEditor`'s `TextInput` is hidden, only taking the keyboard. A visible input over the canvas can't match: React Native lays out text differently from a Skia paragraph, and can't draw the outline, per-line boxes, or a stretched layer. Skia's `getRectsForRange` gives an empty line, or a line of only whitespace, no box, so caret geometry measures a copy of the text with a filler on each empty line (`caretText` in `model/textEditing.ts`).
- `CI=1 npx expo start` turns off Metro's file watching: the bundle keeps the code it started with, and edits never reach the page. Start the dev server without `CI` when you're changing code.
- On web, `Pressable` fires `onPress` from the DOM `click`, which bubbles from any child, including a `TextInput` that natively would take the touch itself. Don't wrap an input in a tap-to-dismiss `Pressable`: put an `absoluteFill` `Pressable` behind it as a sibling, and give the input `position: "relative"`. RNW leaves the `<textarea>` static, and CSS paints static elements under positioned ones, whatever the DOM order.
- React Native defines `window` on native too, without `addEventListener`, so `typeof window === "undefined"` doesn't guard browser-only code: calling `window.addEventListener` there throws. Check `Platform.OS === "web"` instead.
- React Native Web's `AccessibilityInfo.announceForAccessibility` is a no-op too. To tell a screen reader about a change that has no focus of its own, render `Announcement` from `ui/`, which is a hidden live region on web and the native announcement elsewhere.
- React Native Web's `Alert.alert` is a no-op. Use `showAlert` from `ui/`. A plain `Alert` inside `usePreventRemove` blocks navigation on web with no way out.
- To test the photo picker in the browser pane, don't patch `input.click()` or wait for the input with a `MutationObserver`: `expo-image-picker` appends its `<input type=file>` and dispatches a synthetic click in the same synchronous step, so an observer runs too late and the pane cancels the real file dialog. Listen on `window` in the capture phase instead. On the input's `click`, `preventDefault`, set `files`, and dispatch `change` from a `setTimeout`. Stop the input's `cancel` from propagating, or the picker's handler runs twice and throws a `removeChild` error.
- A gesture-handler `Pan` with `minDistance(0)` activates at touch-down on web, but on iOS only once the finger moves, so a tap there never reaches `onEnd`. To act on a tap too (the paint gesture's dot), commit from `onFinalize`, and cancel on a second finger yourself (`numberOfPointers`, `onTouchesDown`) rather than with `maxPointers`, whose failure looks the same as a tap's.
- Gesture handler's `Gesture.Simultaneous` doesn't carry its relations into a `Simultaneous` nested inside it (`SimultaneousGesture.prepare` relates only its own children), so gestures in the inner group aren't simultaneous with the outer group's: they race, and the first to activate cancels the other, with no error. To run a gesture alongside a composed one, add it at the top level as leaves (`Gesture.Simultaneous(composed, ...other.toGestureArray())`), as `EditorCanvas` does with the view's pinch and pan.
- To drag a gesture-handler gesture in the browser pane, use the `computer` tool's `left_click_drag`. Synthetic `PointerEvent`s dispatched from JavaScript don't work: RNGH calls `setPointerCapture`, which throws for a pointer the browser didn't create, and every move raises another error overlay. `left_click_drag` sends a single move, though, and a Pan counts translation from where it activates (on web and iOS alike), so a Pan with an `activeOffset` sees no translation at all. Drive those with several `Input.dispatchMouseEvent` moves in headless Chrome over CDP.
- The worklets Babel plugin turns each `"worklet"` function declaration into a constant that captures the helpers it calls when it's defined, so it isn't hoisted. A worklet that calls a function declared further down the file throws "Cannot access 'x' before initialization" as the module loads (on web, a server error on every page). Declare helpers above the worklets that use them.
- On web, Skia can drop redraws asked for while its canvas surface is still being set up. A scene whose only changes after mounting come from shared values (an opening animation, say) can stay blank until something else redraws it. Mount the drawing once the view has a size, as `EditorCanvas` and `CropCanvas` do.
- Geometry that gestures need on the UI thread (in `model/geometry.ts`, `model/strokes.ts`'s hit testing, `model/layers/shape.ts`'s line checks, `render/layerTransform.ts`, `screens/editor/canvas/viewport.ts`, `screens/editor/canvas/shownViewport.ts`, `screens/editor/canvas/handleGeometry.ts`, `screens/editor/canvas/handleMetrics.ts`, `screens/editor/canvas/pointerTravel.ts`, `screens/editor/canvas/shapeDrag.ts`, `screens/editor/tools/crop/cropGeometry.ts`, `screens/editor/tools/crop/cropDrag.ts`, `screens/editor/canvas/hitTest.ts`, `screens/editor/canvas/snapping.ts`, `screens/editor/canvas/selectionBarPlacement.ts`, `screens/editor/tools/layers/layerReorder.ts`, and `screens/editor/shell/dialDrag.ts`) is marked `"worklet"`. A worklet can only call other worklets, so a new helper called from one needs the directive too. It's just a string, so `model/` stays free of React Native.
- `scheduleOnUI` on web runs its worklet a frame later (a microtask, then `requestAnimationFrame`), while a shared value written from JS there changes at once. Where that frame matters, call the worklet directly on web, as `syncLiveTransform` does. On native, a JS write is scheduled on the UI thread anyway, so a worklet that must read and write shared values atomically (say, to check what a gesture holds) belongs in `scheduleOnUI`.
- `expo-file-system` (SDK 57) has no web implementation: `File` and `Directory` are empty stubs there. Anything stored with it on native needs its own `.web.ts` (projects use IndexedDB). On native, `move` and `copy` are async; `moveSync`/`copySync` are the synchronous versions.
- The iOS Simulator tool's `text` action returns before the app has handled the keystrokes, so a tap right after it (say, on Done) can reach JS before the text does and act on an empty input. Screenshot to confirm the text landed before tapping.
- The iOS Simulator tool's `screenshot` can return a frame from before the last tap or touch path took effect. Before deciding a tap did nothing, or that something stayed on screen after a gesture ended, take a second screenshot.
- Taps sent to the iOS Simulator tool back to back can land about 10ms apart, and React Native then never sees the second (no `touchstart` in JS at all), though no finger could tap two buttons that fast. Before calling a lost tap a bug, check `xcrun simctl spawn booted log show --predicate 'eventMessage CONTAINS "presence: touching"'` for how far apart the contacts were, and space taps out with a screenshot between them.
- React Native's style types don't allow web-only CSS values (`cursor: "nwse-resize"`, `outlineStyle: "none"`), so those need an `as unknown as ViewStyle`/`TextStyle` cast. Keep it inside a `Platform.OS === "web"` branch.
- Metro prefers a platform file only over a file with the same extension: it tries `.web.ts`, `.ts`, `.web.tsx`, `.tsx` in turn, so `foo.ts` silently wins over `foo.web.tsx`. Give a `.web` file and its native counterpart the same extension (`ui/showAlert.tsx` is `.tsx` for this, though it has no JSX). When web runs native code, check which file the bundle names before debugging the code. A `.web` file can import only types from its counterpart (`./Tooltip`): on web that path resolves back to the `.web` file itself, so a value imported from it is undefined.
- React Native Web's `Pressable` passes `hovered` to its `style` and `children` callbacks, though React Native's types only declare `pressed`. Read it with `interaction()` from `ui/interaction.ts` (it's always false on native), and ease the change with `webTransition` from `ui/theme.ts`. For hover over a group, such as a card and a delete button beside it, put `onPointerEnter`/`onPointerLeave` on a wrapping view and only count `pointerType === "mouse"`, or a touch reads as a hover.
- On web, Reanimated renders an `Animated.View`'s style inline, so `pointerEvents: "box-none"` there is silently dropped (RNW implements it with a class), and the view swallows every click in its bounds. Put `box-none` on a plain `View` around it. To animate such an overlay out, keep that plain View mounted and toggle only the animated child, as `LayersPanel` does.
- On web, a Reanimated `entering` animation on a view mounted inside a parent that's itself animating in (a `BottomSheet` sliding up) can pin it with an inline `top` measured mid-animation and drop its static `transform`: Export's highlights landed a row too low. For a small appear animation, drive a shared value from a mount effect instead, as `ui/Highlight.tsx` does.
- For a gradient behind a view, use `gradientBackground` from `ui/gradient.ts` with a CSS `linear-gradient(...)`: React Native takes it as `experimental_backgroundImage`, which React Native Web ignores, and web needs CSS `backgroundImage`, which RNW passes through untyped. Fade to a color at zero alpha (`rgba(255, 255, 255, 0)`), not `transparent`, which can pass through gray. It saves a Skia canvas (and, on web, a WebGL context) for a control's backdrop.
- On web, a vertical `ScrollView`'s `onLayout` width includes its scrollbar. To fit a row of tiles to the width (the sticker sheet's grid), measure a `View` inside the scroll view instead.
- A link to a page renders through Expo Router's `Link`, which is an `<a href>` on web (it can open in a new tab, and crawlers follow it) and navigates in the app on a plain click. `Link asChild` hands its child a merged `style` array, so a `Pressable`'s style function is never called: put the look that follows `hovered` and `pressed` on a view inside, from the `Pressable`'s children callback (`AboutLinks` on home).
- React Native Web's `Image` calls `onLoad` with the DOM load event, which has no `nativeEvent.source`. Read an image's size with `Image.getSize`, which works on both.
- The web app is a static export hosted on Vercel, which only serves files: `vercel.json` turns on `cleanUrls` (`/create` → `create.html`) and rewrites each dynamic route to the page Expo exports for it. `cleanUrls` renames every page without its `.html`, so a rewrite names it that way (`/projects/:id` → `/projects/[id]`); one to `/projects/[id].html` finds nothing and 404s. A new dynamic route needs a rewrite there too, and a route that moves needs a redirect there: the `redirects` option of Expo Router's config plugin doesn't run in a static export's client. Vercel answers an unknown path with `404.html`, which `build:web` copies from Expo's `+not-found.html`. Previews sit behind Vercel's login, so check routing locally: `npx vercel build` (with a `.vercel/project.json` giving `"framework": null`, `"outputDirectory": "dist"`, and `"buildCommand": "npm run build:web"`) writes the routes Vercel will follow, with each page's served path under `overrides`, to `.vercel/output/config.json`.
- A project's routes (`/projects/[id]`, `/projects/[id]/export`) can be the first screen, from a link, a reload, or the browser's Back and Forward. The editor opens its project itself with `useProjectSession`; export sends the user to the editor to do that. Export is presented as a `transparentModal` sheet (`app/_layout.tsx`), so the editor stays mounted behind it, unfocused, with its keyboard shortcuts off. Don't set `unstable_settings.anchor` to put the home screen underneath: Expo Router hands the anchor the link's params, so going back shows `/?id=…`. The editor's Back replaces the route with home when there's nothing behind it.
- Tests live in `__tests__/` in the directory they test, import the module under test with an explicit `.ts` extension, and start with `/// <reference types="node" />`: Node's type stripping needs the extension, and TypeScript 6 no longer includes installed `@types` packages by default. Node can't resolve the `@/` alias or load React, so a tested module imports its dependencies by relative `.ts` path and nothing React-based at runtime. Store slices follow this: they import only types from `zustand`, and tests build a vanilla store with `createStore` from `zustand/vanilla`.
- While the Browser pane is hidden, its page runs about two animation frames a second (`document.visibilityState` is "hidden"). Skia and Reanimated draw on frames there, so anything timed against drawing (a quick succession of edits, an image freed after a redraw) can fail in the pane and nowhere else. Check timing-sensitive behavior in headless Chrome over CDP, which runs at 60 frames a second. WebGPU work can stall there entirely (an ONNX Runtime session never finished a run), so time GPU inference over CDP too; Chrome there finds the Mac's Metal adapter.
- In headless Chrome over CDP, `--window-size` without a display defaults the viewport height to 1 pixel unless `Target.createTarget` is called with `newWindow: true` and explicit dimensions.
- Floating overlays over the canvas that allow interacting with both the overlay card and canvas elements underneath (such as candidate selection in detection) require wrapping the animated card in a plain `View` with `pointerEvents="box-none"`, as Reanimated drops `pointerEvents="box-none"` when passed inline on web.
- Photos shared from other apps come in through `modules/share-target`: an iOS share extension (a target its config plugin adds to the Xcode project) and an Android `ShareActivity`. Both copy the photo where the app can read it (the App Group `group.<bundle id>` on iOS, which Expo autolinking reads from the entitlements and lets `expo-file-system` open; the cache on Android, since the content URI's grant belongs to the share activity) and open `<scheme>://share?file=<name>`. `src/app/+native-intent.ts` turns that into home's `shared` param. A link that arrives while the app runs must go through `router.dismissTo`: a plain navigate pushes a second home over the editor.
- To test sharing on the iOS simulator, `xcrun simctl addmedia` a photo and share it from Photos, or put a file in `xcrun simctl get_app_container <udid> com.nverk.tuck group.com.nverk.tuck`'s `shared-photos/` and `simctl openurl` the link. A cold start in the development build stops at the dev launcher, which passes the link on once a server is picked. A Fast Refresh re-runs `redirectSystemPath` with the last link as `initial` and doesn't reliably apply its result, so judge cold starts only after a real terminate. On Android, `am start -a android.intent.action.SEND -t image/jpeg --eu android.intent.extra.STREAM content://media/external/images/media/<id> --grant-read-uri-permission` opens the system chooser.
- Biome's `noRestrictedImports` matches an import's text, not the file it resolves to, and reads a `group` like `.gitignore`: the last pattern that matches wins, so a ban listed after a `!` exception takes back part of it, and one listed before is undone by it. A relative ban counts levels from the importing file, so it needs a pattern for each depth (a test sits a level below its module), and a negation like `!../../../**` allows everything under that folder, including a path that climbs to `src/` and back down into another screen. Only one override applies to a file, the last in `biome.json` that matches it, so each override repeats the bans it needs.

## Project Structure

- Keep imports flowing one way: `app` → `screens` → `photos` / `projects` / `render` / `store` → `model`, with `ui/` beneath anything that draws, `platform/` (the OS ports: haptics, preferences, temporary files, the service worker) beneath the screens and `ui/`, and `lib/` beneath everything. Route files only register screens; screens compose the shared capabilities (the home and editor screens hand `renderThumbnail` from `render/` to `closeProject`), and don't import each other. A folder lives in the screen that uses it, or at `src/` when several screens do. `model/` stays plain TypeScript (no React, React Native, or Skia), `store/`, `photos/`, and `projects/` import only `model/` and `lib/`, `render/` imports only `model/`, `lib/`, and `ui/`, `ui/` never imports app code (only `platform/preferenceStore`, which `theme.ts` reads at launch), and `platform/` and `lib/` import only themselves. `biome.json`'s `noRestrictedImports` overrides enforce this: change them when the structure changes.
- `screens/` has a folder per screen: `home/`, `create/`, `editor/`, `export/`, and `info/` (`InfoPage`, Settings, the support, privacy, and licenses pages, which the stores link to, and the 404 page). Export options, saving, sharing, and the render hook belong to `screens/export/`. Photo import, project storage, and drawing a document (`render/`: each layer type's view in `render/layers/`, `LayerContent`, `useDecodedImage`, which the editor's canvas, crop, and export share, and offscreen rendering for export and thumbnails) are shared, in `photos/`, `projects/`, and `render/`. Reusable controls, including `Popover`, and `theme.ts` live in `ui/`; the site's address and the support email, in `lib/site.ts`.
- `model/` is the document and the geometry it's built from. Each layer type has a file in `model/layers/` with its type, its factory, its check for a saved layer, and helpers only it needs (`base.ts` holds what every layer shares, and `layer.ts` the `Layer` union and what works on any layer); `document.ts` holds the document, its groups, and whole-document checks. Callers import from the file that declares a name: there's no barrel. Pure logic that only the editor uses (`canvas/viewport.ts`, `canvas/layerBounds.ts`, `canvas/handleGeometry.ts`) lives in `screens/editor/`, with its test in `__tests__/`.
- `screens/editor/` keeps its tools in `tools/`, a folder per tool: `adjust/`, `crop/`, `cutout/`, `draw/`, `find/`, `layers/`, `redact/`, `stickers/`, and `text/`. Tools don't import each other. A tool's settings module (`brushSettings.ts`, `redactSettings.ts`, `cutOutSettings.ts`) holds its rules: which size the sub-tool in use keeps, and what counts as a brush. Its panel file holds one table per list of choices (`BRUSHES`, `REDACT_TOOLS`, `CUT_TOOLS`, `BRUSH_EDGES`; Redact's effects are shell's `EFFECTS`, which Find reads too). Its dock panel, bar, and tray read both, and keep only what differs between them: what a press on the sub-tool in use does, how a choice is drawn, and its label. What they share is in `canvas/` (the document's view, its gestures, selection handle geometry, touch metrics, cursors, and the viewport, which crop draws with too) and `shell/` (the dock, the context bar, the toolbar, the header's actions, layer actions, the selection bar, tool buttons, trays, the dial, and color swatches). Only `detection/` (`imageDetection.ts` and `subjectDetection.ts`) imports `image-analysis`, and the Find and Cut out tools call it from there. `shell/` and `tools/stickers/` import nothing else from the editor (except `shortcuts.ts` for tool key labels), `session/` and `detection/` import nothing else from the editor, `canvas/` imports no tool, `session/`, or `detection/`, and only `tools/crop/` imports `canvas/`. `session/` opens the project and autosaves it (`useProjectSession.ts`, `useAutosave.ts`, `SaveErrorBanner.tsx`). The root holds `EditorScreen.tsx`, `EditorDock.tsx` (`TOOL_VIEWS`, what each panel shows in the dock, the bar, the trays, and the inspector: a tool's views go there, while its title and actions stay in `editorChrome.ts`), `EditorRail.tsx`, `EditorInspector.tsx`, and `editorChrome.ts` (which chooses the panel, Done, and Cancel for both layouts), which compose the folders, and what spans the editor: adding images (`useAddImage.ts`), its mode, how its tools are built and how they open and close (`useToolLifecycle.ts`: `useEditorTools`), its keyboard shortcuts, and the edit notice (`useEditNotice.ts`: deleting, and redacting what Find found, with Undo).
- `store/` holds only state shared across screens, as Zustand slices combined in `store/index.ts`; state local to one screen stays in `useState`, or `usePreference` from `platform/` when it should outlast the session (a tool's settings). Give a preference a parser beside the settings it holds that makes a valid value of anything saved, since an older build or a damaged file may have written it. `render/` takes plain props and never reads the store, so export can render any document. Select the narrowest value a component needs.
- `modules/` holds local Expo modules with native code, autolinked without a `package.json` entry. The app imports `modules/image-analysis` as `image-analysis` (a `tsconfig.json` path).
- Only routes go in `src/app/` — expo-router turns every file there into a screen. Keep screen implementations in `src/screens/`.
- Take colors from `colors` in `ui/theme.ts`, never literals that assume one palette: it's the day or the night palette, picked at launch from Settings' choice or the system's setting (`colorScheme`), and React Native styles read it once, so nothing switches while the app runs: changing the setting reloads the app (`reloadAppAsync`). `+html.tsx` applies a chosen palette to the web page before the app loads. Draw over the photo in `colors.selection`, which reads in both. A fade to a palette color uses `fadeTo` from `ui/gradient.ts`.
- Take text sizes and weights from `typography`, corners from `radii`, and gaps from `space` in `ui/theme.ts` rather than writing numbers; a one-off gap that matches no step of the scale may stay literal. Literal font sizes are left only for the Anton display text (the wordmark and home's headings), font previews, and the text editor's hidden input (16px, or iOS Safari zooms into it). Circles keep half their size as a radius.
- Name component files in PascalCase and other modules in camelCase. Prefer growing an existing file over adding a single-use one; split a file when it gains a second responsibility.
- A doc comment longer than a short paragraph is a sentence on what it is, then a short list, one line per behavior or parameter.
- `docs/interactive/` is a separate Vite app of interactive lessons, with its own `package.json` and `tsconfig.json` (the root `tsconfig.json` excludes it). Lessons import the real `src/model` through its `@model` alias and quote code with `SourceView` by declaration name, so renaming or retyping something a lesson covers breaks its build (`npm run build --prefix docs/interactive`, which CI runs) or shows the lesson's "has moved" notice: update the lesson in the same change. Its rendering lessons run `src/render/` on CanvasKit through Vite (see its README), so a change to `render/`'s imports (a new Expo module, a native-only file without a `.web` counterpart) can break that build too.
- Name the editor document `document` (not `doc`). TypeScript's DOM lib declares a global `document`, so a missing parameter or destructure still type-checks against the browser global; watch for that when renaming.

## Git Commits

- Use Conventional Commits format for commit messages, such as `feat: add text editing` or `fix: handle invalid image input`.

## Code Checks

- After code changes, run `npm run check` to verify formatting and linting, `npm run typecheck` for TypeScript, and `npm test` when touching `model/`, store slices, or other pure modules (it runs the tests under `modules/` too). Run `npm run build:web` after changing platform files (`.web.ts`), the entry files, or imports TypeScript doesn't check (assets, untyped imports): it bundles with Metro, which catches an import that won't resolve. It doesn't run the app, since the static export renders only an empty shell. CI runs all four. Use `npm run format` to apply formatting fixes, and run `npm run lint` when checking lint rules only.
