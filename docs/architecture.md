# Architecture

The editor keeps the original photo and represents edits as an
`EditorDocument`. Layer transforms use document-space coordinates, independent
of the preview size. The canvas fits that document into the available screen
space, while gesture state is held outside React during an interaction and
committed to the document when the gesture ends. Export and project thumbnails
render the same document offscreen with Skia.

Skia draws the whole editing surface: the canvas is never a set of positioned
React Native views, which only make the chrome around it (toolbars, panels,
dialogs). The editor is the project's own, with no commercial photo-editor SDK,
and native code stays behind narrow modules (`modules/`) rather than taking
over any of the editor.

## The shape

Each area of `src/` has one job, and imports flow from the top of this list
down:

- **Routes** (`app/`) name the URLs and hand each to a **screen** (`screens/`):
  Home, Create, Export, the info pages, and the editor's route.
- **Session** (`session/`) owns the active editing session across screens:
  starting from a photo or blank canvas, opening a saved project, autosaving,
  and closing a session with its thumbnail when leaving.
- The **editor** (`editor/`) is a component the app composes rather than a
  screen. It holds the document (`document/`) and a folder per layer type
  (`layers/`), with every edit to them, in plain TypeScript that Node's tests
  run directly, and draws a document with Skia (`render/`) for its canvas,
  export, and thumbnails alike. It knows nothing of projects, photos, or
  navigation: the app hands it an `EditorHost` for those, and a list of tools,
  each a folder of its own.
- **Photos** (`photos/`) and **projects** (`projects/`) are the app's concepts:
  picking and importing images with their canvas preview in one pass, and
  keeping each session as a project on the device.
- Underneath, `site/` holds what the web site says about itself, `ui/`
  the shared controls and theme, and `platform/` the OS ports (preferences,
  haptics, files).

[Modules](#modules) says what each folder holds, and
[Boundaries](#boundaries-and-platform-files) the import rules that keep it
that way.

## Modules

- `src/app/` holds only thin Expo Router route files (every file there becomes a screen). A project's editor is at `/projects/[id]` and its export at `/projects/[id]/export`, so a link or a reload opens the project from storage (`useProjectSession`); `vercel.json` serves those routes from the static export.
- `src/screens/` has a folder per screen: `home/`, `create/`, `editor/` (the editor's route), `export/`, and `info/` (`InfoPage`, Settings, the support, privacy, and licenses pages, which the stores link to, and the 404 page). The home screen starts from a photo, a pasted or dropped image, a photo shared from another app, or, through Create, an empty canvas at a preset or custom size. Screens call `src/session/` to start, open, or end a project session and don't import each other. A folder lives in the screen that uses it, or at `src/` when several screens do.
- `src/screens/editor/` is the editor's route: `EditorScreen` opens the project from its params (`session/useProjectSession`), shows it opening or why it couldn't, saves it as it's edited (`session/useAutosave`), and hands `<Editor>` the document and its host.
- `src/screens/export/` chooses output sizes and format, then saves the image to Photos, copies it, or shares it: as JPEG, or as PNG when some of the canvas is transparent.
- `src/session/` is the single owner of the active project session: `projectSession.ts` (plain TypeScript, tested in Node with fake storage and open document controller) starts a session from a photo or blank canvas with an unsaved fallback when storage fails, opens a saved project or a copy after closing any previous session, renders thumbnails with the project's preview URIs, and ends the session; `appSession.ts` wires the app-wide singleton controller; `useProjectSession.ts` provides React hooks (`useProjectSession`, `useSessionProjectId`, `useRouteDocument`, `useHasOpenSession`) and route integration; `useAutosave.ts` queues and flushes autosaves and warns before unload on web.
- `src/editor/` is the interactive editor. It has two entry files, the only ones the rest of the app imports. `core.ts` (`@/editor/core`) is plain TypeScript: the document and its checks, the layer types and their factories, and `Size`, for `projects/`, `photos/`, the screens, and their Node tests. `index.ts` (`@/editor`) is the rest: `Editor`, the `EditorHost` type, what draws a document outside the editor (`renderDocument` and `drawOffscreen` for export, `renderThumbnail` for project thumbnails, `preloadFonts` and `resetFailedFonts` for the root layout, and `LoadFonts` for the editor's route, which suspends on the text fonts while no other page waits for them), and the open document controller (`openDocument.ts`) that `src/session/` opens, closes, and reads: the document open in it, or none, and the key the app opened it with (a project's id, or null when it couldn't be saved), through `useOpenDocument` in React and `getOpenDocument` outside it. The editor uses the key only as Cut's cache key. The editor knows nothing of projects, photos, or navigation: the app hands it an `EditorHost` (`editorHost.ts`), which picks and imports photos, keeps an image the document gains, names the document and says whether it's saved, says whether the editor is in front, and leaves or opens export. The editor declares the host's types (the picked image and its size limits), which `photos/` and `projects/` meet without the editor importing either. Every part that needs the host runs in `Editor`'s body, so `Editor` hands each what it needs as arguments. The rest is in a folder per part:
  - `store/` holds the editor's state as one Zustand store, outside `<Editor>` since a session opens a document before the editor mounts: `index.ts` makes `useStore`, `editorSlice.ts` owns the document, its key, selection, and the compact action table that mutates them (the edits themselves are beside what they edit, in `document/` and `layers/`), and `history.ts` owns undo history and tool sessions (`ToolSession`, `undoSteps`, `stepsByMark`, whose changes become one undo step when the tool is done, unless its spec keeps one per mark, as Pen, Shape, and Redact do, or one per swipe, as the Eraser does). Nothing outside the editor reads it but through `openDocument.ts` (or `src/session/`). State local to one screen stays in `useState`, or `usePreference` from `platform/` when it should outlast the session (a tool's settings), which every caller of a key shares; a preference has one parser beside its settings that makes a valid value of anything saved, since an older build or a damaged file may have written it. Components select the narrowest value they need.
  - `document/` is the document and what spans it, as plain TypeScript: no React, React Native, or Skia. The document is the canvas (its size, and a background fill or transparency) and its layers, which may be none. `document.ts` holds the document, its groups, and whole-document checks; `documentEdits.ts` what changes the canvas (cropping's `reframe`, `setBackground`); `geometry.ts` the shapes and transforms everything measures with; `values.ts` the checks a saved file's fields share.
    - A photo is an image layer like any other: a document's own photo starts locked, and can be unlocked, reordered, hidden, or deleted; photos added later start unlocked. `framing.ts` moves the framing's anchor (the lowest visible locked image, or with none, the canvas itself) to a new place on a new canvas and keeps every other layer over the same spot, which is all cropping, turning, and flipping are.
    - Imported photos are already upright: the import's re-encode applies EXIF orientation and writes no orientation tag (web re-encodes through a canvas), so a layer's `width` and `height` are the upright size. `image-analysis` applies EXIF orientation itself, so its rectangles are in upright pixels for any file.
  - `layers/` has a folder per layer type (`image/`, `text/`, `drawing/`, `shape/`, `redaction/`), each holding everything about that type: its file (`text.ts`: its type, its factory, its check for a saved layer, and helpers only it needs), its edits (`textEdits.ts`), its view in document space (`TextLayerView.tsx`), and anything else only it needs (`image/` holds `adjustments.ts` and the cut-out mask, `mask.ts`; `drawing/` how strokes group into marks, `marks.ts`; `shape/` its geometry, `shapeGeometry.ts`; `text/` `textLayerLayout.ts`). At its root, `base.ts` holds what every layer shares, `layer.ts` the `Layer` union and what works on any layer, `layerEdits.ts` the edits any layer takes (hiding, locking, deleting, moving, transforming), `strokes.ts` the strokes drawings, cut-outs, and redactions share, `LayerContent` draws any layer, and `layerTransform.ts` places one; the canvas and Crop use both. The Layers panel lives in `chrome/layersPanel/`, where any layer is hidden, locked, deleted, or reordered; a mark's row is named from its kind and color (`markName`, with `shell/swatches.ts`) and shows a picture of its ink, drawn offscreen one at a time and cached by its strokes (`render/markThumbnail.tsx`), never a canvas per row.
  - The lowercase `.ts` files in `document/` and `layers/` are plain TypeScript, which Node's tests run; the views and `layerTransform.ts` are the only files there that use Skia. Callers import from the file that declares a name: inside the editor there's no barrel. Pure logic only the canvas uses (`canvas/viewport.ts`, `canvas/layerBounds.ts`, `canvas/handleGeometry.ts`) stays in `canvas/`.
  - `render/` draws a whole document: the decoded-image cache and `useDecodedImage`, `fonts.ts` (the bundled text fonts, so text renders identically on iOS, Android, and web; `renderDocument` awaits them, and the editor's route suspends on them), `drawOffscreen`, `DocumentRenderScene` (the scene export draws), and `renderDocument`, which draws offscreen for export, project thumbnails, Cut, and saved stickers. `layers/`'s views and `render/` take plain props and never read the store, so export can render any document.
  - `canvas/` holds the canvas pieces every mode shares: `EditorCanvas` and `EditorScene` (which compose the canvas with each input's gestures and overlays), `useCanvasInput` and `canvasInput.ts` (what input on the canvas does: the eyedropper's pick, the open tool's input, or selecting, whose kinds name what they do rather than a tool), the viewport and zoom (which Crop draws with too), live layer transforms (`SceneLayer`, `LiveLayerContent`), the selection overlay, handles and cursors, hit-testing, snapping, touch metrics, the stroke pipeline Pen, Shape, Eraser, Redact, and Cut share (`useToolStroke` for the gesture, landing id, and `strokeIntent`, and `strokes/` with one file per stroke kind—`draw`, `erase`, `redactBrush`, `redactBox`, `shape`, `cut`—plus `useEraseTracking` for the Eraser's UI-thread hit tracking), the gestures and drawing of the `regions` and `dial` inputs (`useRegionTap` and `RegionOutline`, which Find's found regions use; `useDialDrag`, the sideways drag that turns Adjust's dial), and the checkerboard that stands for transparency (`CanvasBackground`), which no render of the document draws.
  - `tools/` has a folder per tool in the dock: `adjust/`, `crop/`, `cut/`, `eraser/`, `find/`, `pen/`, `redact/`, `shape/`, `stickers/`, and `text/`. Remove BG shares `cut/` with Cut, since both select subjects through `useCutOut.ts`. A tool reaches the canvas only through its input (`canvas/canvasInput.ts`), whose gestures and drawing are the canvas's, its draft (`views.Draft`, which the scene draws in place of the layer it edits), or a canvas of its own in the stage's place (Crop's `Stage`). Tools with subtool choices (`pen/`, `shape/`, `cut/`, `eraser/`) declare `variants`, `activeVariant`, `selectVariant`, and `variantEntry` in `tools/defineTool.ts`, which the rail and dock display as corner flyout indicators (`◢`).
    - `pen/`, `shape/`, and `eraser/` split freehand drawing, vector geometry, and erasing into three tools of their own, so each keeps a short row of options in the context bar and dock.
    - `pen/` draws marks: one drawing per word, arrow, or circle, grouped by pause, distance, and style rather than by session (`continuesMark` in `layers/drawing/marks.ts`). A stroke continues the last stroke's mark when it's in the same tip and color, begun within `MARK_PAUSE_MS` and `MARK_GAP` widths of its visible ink (or `MARK_NEAR_PAUSE_MS` and `MARK_NEAR_GAP`), and otherwise starts a mark; it never joins an older mark by itself, and leaving Pen ends the mark. The gesture gives each stroke when it began and ended; nothing about it is saved. Opened from the toolbar, Pen lets go of the selection, as the Eraser does, so it starts a new mark. Opened from a mark's actions, it adds to that mark while the style matches, shows the mark's tip, color, and size (`withSelectedMark` in `penSettings.ts`, as Shape shows a selected shape's), keeps the mark outlined, and changing them restyles every pen stroke in it at once (`restyleDrawing`, one undo step each; a new tip sets the blend, erasers stay). A mark whose strokes form pieces that don't touch (`drawingPieces`, which counts only ink no eraser cleared, whole strokes only) offers Separate in the selection bar (`LayerSelectionBar`), which splits it into one mark per piece in its place, the first keeping its id (`separateDrawing`).
    - `eraser/` has a canvas input of its own (`erase`, with an optional `scope` naming the one drawing it keeps to). Opened from the toolbar it lets go of the selection (`startsUnselected`) and reaches every unlocked drawing and shape, never a photo, text, a sticker, or a redaction. Its stroke joins each unlocked, visible drawing it crosses, whatever its blend (`eraseStroke`); strokes it leaves pointless are pruned (`pruneErased`), and a drawing left with no ink is removed. While it drags, it clears ink live in each drawing it reaches from one shared path, and dims each shape it crosses (`crossed`, tested on the UI thread); a swipe that removes a whole drawing or shape says so in the notice. On web a ring at its size follows the pointer. Opened from a selected drawing's actions, it keeps to that drawing (`scope` from `ToolEnv`'s `on`): the drawing keeps its outline, every other drawing and shape dims to a third on screen, shapes stay, and erasing the drawing away closes it. Its settings (`eraserSettings.ts`) hold its mode, a remembered preference: Eraser clears where it passes; Stroke eraser (`mode: "stroke"` on the same `erase` input) takes each stroke it touches whole (`eraseWholeStrokes`, with `strokesHitBy` in `layers/strokes.ts` shared by the canvas and the edit, so they agree on what goes), dimming each one as it's crossed (`crossedStrokes`, on the UI thread, with a haptic tick off web) and, on web, the one under the pointer.
    - `find/` holds face and text detection (`useImageDetection`, `FindPanel`), and the review that zooms to each region (`useReviewZoom`, in Find's hook rather than a view, which the tray and the layout mount and unmount).
    - `cut/` holds subject and object selection, mask refinement brushes, invert, and what Cut does with a selection, chosen in its Apply menu (its Done puts it down unchanged): copy it to a new layer (`addCutCopy`), keep only it, remove it (flattening it in `cutMask.tsx`), redact it in a mask-shaped redaction, or save it as a sticker. Beside it, Remove BG (`removeBgTool.ts`) is an action: it cuts an image down to its subjects in one undo step, using the subjects Cut found in the session (`subjectMaskOf`), and its notice's Refine opens Cut on the image.
    - `adjust/` holds color adjustments: its `dial` input carries the drag's dial and the photo it changes, which the canvas draws live (`LiveAdjustment`).
    - `crop/` crops, turns, flips, and straightens the photo (the lowest locked one, or just the canvas without one) and expands the canvas around it. Its hook keeps a draft, started from the document each time it opens, which its Done reframes the document to in one step; its spec takes the keys (`takesKeys`). `CropCanvas` is its `Stage`, and `CropPanel` holds its tabs, its bar, and its `Controls`. Its geometry is in `cropGeometry.ts` and its box dragging in `cropDrag.ts`.
    - `stickers/` holds the sticker sheet and bundled stickers, and lists the ones people save, so a toolbar without Stickers leaves the sheet out. Adding a sticker closes Stickers, so its layer is an undo step of its own, and its layer action keeps a selected photo as a sticker. The photo picker waits for the sheet to finish closing (`sheetDismissed`), since on iPad one opened sooner goes down with the popover.
    - `text/` is typing on the canvas and styling text, open exactly while text is typed: its hook (`useTextTool`) keeps the edit, which its Done adds to the document as one undo step, and its views are the style panel (with inline color sliders in the dock) and bar (`TextStylePanel`), the draft with the package's `Caret` and `SelectionHighlight`, and the package's `HiddenTextInput` (`TextEditing`: its `Draft` and `Input`). It edits a selected text layer in place on a tap (`edit`), and its panel styles one with nothing open (`stylesLayer`). The canvas's `editText` input carries what the package's `useCanvasTextGesture` needs (`canvas/useEditTextGesture`, which maps the viewport to the layer's space and leaves the hit test to the tool), so the canvas assumes no text layer.
  - A tool's settings module (`penSettings`, `shapeSettings`, `eraserSettings`, `redactSettings`, `cutSettings`, Crop's `cropOptions`) holds its rules: which size the sub-tool in use keeps, what counts as a brush, which ratios Crop offers. Its panel file holds one table per list of choices (`TIPS`, `REDACT_TOOLS`, `CUT_TOOLS`, `BRUSH_EDGES`, `CROP_TABS`; Redact's effects are shell's `EFFECTS`). Its dock panel, bar, and tray read both, and keep only what differs between them: what a press on the sub-tool in use does, how a choice is drawn, and its label.
  - `savedStickers/` keeps the stickers people save, outside any project: the pure index (`savedStickers.ts`), its storage (and its `.web` file), and `saveSticker.ts`, which saves one and tells the Stickers sheet's list (`onStickerSaved`), and renders a cut-out as one. Stickers and Cut both save stickers.
  - `shell/` holds the controls every tool's panel and chrome are built from: the wide editor's context bar, the toolbar list, the dial, color swatches and the color options built on them (`ColorOptions`, `ColorChip`), and layer actions.
  - `chrome/` holds the frame and layout: `EditorHeader`, `EditorRail`, `EditorInspector`, `PanelViews` (which shows the views of the open tool or of the tool styling the selection, or a selected layer's actions, in each slot), `LayerSelectionBar`, `Dock`, `ToolsPanel`, `HeaderActions`, `SelectionBar`, `DevHud`, `SaveErrorBanner`, `ShortcutsOverlay`, `useEditorLayout`, `editorFrame`, `editorChrome` with `useEditorChrome` (which derives the toolbar entries with variants and busy states, the tool starters, and the layer actions), and `layersPanel/` (where any layer is hidden, locked, deleted, or reordered; a mark's row is named from its kind and color, `markName`, with `shell/swatches.ts`, and shows a picture of its ink, `render/markThumbnail.tsx`, never a canvas per row).
  - How new redactions look (`RedactLook`: the effect, color, and strength) is the editor's, not Redact's: `shell/redactLook.ts` holds it and turns it into a `RedactionEffect`, and `shell/redactStyle.tsx` its controls. Redact, Find, and Cut each add redactions in it, and none opens another: Find's Done adds the regions chosen and closes Find, and Cut's Redact takes back the cut, adds a redaction in its shape, and closes Cut. `shell/useRedactLook.ts` keeps it under its own preference (`redactLook`), which Redact's, Find's, and Cut's hooks and Find's views each read, and which starts from the look earlier builds kept in Redact's settings (`redactSettings`, now only its sub-tool and brush sizes).
  - `detection/` is the editor's only bridge to `image-analysis`: `imageDetection.ts` finds faces and text for Find, and `subjectDetection.ts` selects subjects and objects for Cut.
  - Each tool describes itself in its own folder with a plain-TypeScript `ToolSpec` (`tools/toolSpec.ts`) and a `ToolDefinition` (`tools/defineTool.ts`), whose doc comments are the authoritative contract for every field. `tools/builtInSpecs.ts` and `tools/builtInTools.ts` list the built-in tools by id, and nothing else in the editor imports a tool or branches on a tool id. A tool's hook (`useController`) runs in `Editor`'s body above `EditorContext`, so it reads from `ToolEnv`, the store, and shared preferences, while only a tool's views read `tools/editorContext.ts`.
  - The editor root holds `Editor`, and what spans the whole editor: adding images (`useAddImage`), its mode (`editorMode.ts`, `useEditorMode.ts`), how its tools are built and how they open and close (`tools/useEditorTools.ts`), keyboard shortcuts (`shortcuts.ts`, `useEditorShortcuts.ts`), and the edit notice (`useEditNotice.ts`). The background picker is in `src/ui/` because Create also uses it.
- `src/photos/` picks, pastes, or receives a shared photo and re-encodes both the stored image (JPEG when opaque, PNG when transparent) and its canvas preview in a single pass (`photoImport.ts`, `photoImport.web.ts`). `previewCache.ts` stores the preview alongside the project and, for a project saved before one-pass import or whose cached previews were purged, makes one with the same encoder (`makePreview`).
- `src/projects/` keeps every editing session as a local project: its photos move into it, each as a file of its own, edits autosave, and the home screen lists projects to reopen, rename, duplicate, or delete, each with a thumbnail rendered when its editor closes. `projectFile.ts` is the saved format (versioned, with image layers naming their file in the project); `openProjects.ts` opens, saves, autosaves, adds images to, and closes open projects; `projectLibrary.ts` lists, renames, duplicates, deletes, copies, and refreshes thumbnails of closed projects; and `projectService.ts` composes both over `projectStorage(.web).ts` to provide the project subsystem to `src/session/`.
- `src/ui/` holds reusable controls, including `Popover`, `ColorPicker`, `SwatchChip`, and `FadeRow` (a scrolling row that fades between whole options), `theme.ts`, and `color.ts`: hex colors, averaging, and mixing, in plain TypeScript, which the color picker's HSV math (`hsv.ts`) and the editor share.
- `src/site/` holds what the site says about itself: its address and support email (`site.ts`) and each page's head (`PageHead`), which the routes, Home, and the info screens use.
- `src/platform/` holds the OS ports any caller can use: haptics, preferences (`preferenceStore`, `usePreference`), temporary files, performance spans (`perf.ts`), a file pasted or dropped onto the page (`usePhotoDrop`), and the service worker, each with a `.web.ts` version where the web differs.
- `modules/` holds local Expo modules with native code, autolinked without a `package.json` entry. `modules/image-analysis/` does on-device face, text, subject, and object detection (Apple Vision, Google ML Kit, MediaPipe, Tesseract, and MobileSAM with ONNX Runtime; see [on-device-detection.md](./on-device-detection.md)); the app imports it as `image-analysis` through a `tsconfig.json` path. `modules/share-target/` is the share extension on iOS and the share activity on Android. `modules/process-memory/` reads the process footprint on iOS for the Dev HUD, imported as `process-memory`.
- The repository is a pnpm workspace (`pnpm-workspace.yaml`): the app at the root, `docs/interactive/`, and `packages/*`. `packages/skia-text-input/` (`@tuck/skia-text-input`, private for now) is the canvas text editing the editor builds on. Its `/core` entry is plain TypeScript and Skia's types: word selection, and `createCaretLayout`, which measures where a caret, a selection, and a tap fall in a paragraph the caller builds (`editor/layers/text/textLayerLayout.ts` gives it the text layer's). Its root entry adds the React Native parts (`HiddenTextInput`, `Caret`, `SelectionHighlight`, and `useCanvasTextGesture`, the presses on the canvas), which need Reanimated, Worklets, and Gesture Handler too. Only the editor imports the root entry, so the layer views and the interactive docs load no React Native from it. The app depends on it as `workspace:*`, and its `exports` point at its `.ts` source, so nothing builds it first; `lib/` is built only to pack it (`publishConfig`, its README). A package there lists React, React Native, and any native library it uses as `peerDependencies`, so the app keeps one copy of each, and imports nothing from `src/`.
- `index.ts` / `index.web.ts` are the app entry. On web, it loads Skia's WASM build before any app code runs.

## Boundaries and Platform Files

Imports flow one way: `app` → `screens` → `session` → `editor` and `projects`,
with `photos/` beside them, `ui/` beneath the screens and the editor, and
`platform/` beneath them and `ui/`.

- `photos/` and `projects/` import only `@/editor/core` (by relative `.ts` path, so Node's tests load it). The editor's `store/` imports only `document/` and `layers/`'s plain files. In the editor, `document/` and `layers/`'s plain files import only each other; `layers/`'s views and `render/` import only each other and those. Anything in the editor may import `document/` and `layers/`'s plain files.
- `ui/` never imports app code, except `platform/preferenceStore`, which `theme.ts` reads at launch. `platform/` and `site/` import only themselves, and only routes and screens import `site/`, never the editor.
- Outside `src/editor/`, the app imports the editor only from `@/editor` or `@/editor/core`, and nothing inside the editor imports either: its files reach each other by relative path. The editor imports no route, screen, `session/`, `photos/`, `projects/`, or `expo-router`: what it needs from the app comes through its host. Only `src/session/` imports both `@/editor`'s session and `projects/`.
- In the editor, tools and the Layers panel (`chrome/layersPanel/`) don't import each other. A tool reaches the rest of the editor only through `tools/defineTool.ts`, `tools/toolSpec.ts`, `tools/editorContext.ts`, the canvas's input types (`canvas/canvasInput.ts`), the host's types (`editorHost.ts`), the store, `canvas/`, `shell/`, `detection/`, and `savedStickers/`; the panel through `tools/editorContext.ts`, the store, `canvas/`, `render/` (a mark's picture, `markThumbnail.tsx`), and `shell/`. What reaches a tool at runtime splits the same way: its hook runs in `Editor`'s body, above the context `Editor` provides, so it gets `ToolEnv`, the store, and shared preferences, and only its views read `tools/editorContext.ts`. `shell/` imports nothing else from the editor (except `shortcuts.ts` for the editor's own keys); `detection/` imports nothing else from it; `savedStickers/` imports only `render/` and `layers/`; `canvas/` imports nothing else from the editor but `shell/`, `layers/`, and `render/`, and tools may import `canvas/`, `layers/`, and `render/`.

No tool enforces these boundaries: this list is the rule, and changes when
the structure does. That's on purpose. Encoding them in `biome.json` took over
a thousand lines, so `biome.json` stays small and nothing checks imports. If a
boundary ever truly needs a check, it gets a few lines, not a rule set.

### Extension checklists

- **Add a tool:** create a folder in `editor/tools/<name>/` with `<name>Spec.ts` (`ToolSpec` from `tools/toolSpec.ts`) and `<name>Tool.ts` (`defineTool` from `tools/defineTool.ts`), then register the spec in `tools/builtInSpecs.ts` (and `BUILT_IN_TOOLBAR`, or another tool's `grouped` and `variants` if it sits in a flyout) and the tool in `tools/builtInTools.ts`. Adding a tool adds no case in `Editor.tsx`, `tools/useEditorTools.ts`, `editorMode.ts`, or `chrome/editorChrome.ts`.
- **Add a canvas stroke kind:** add its `CanvasTool` and `ToolStroke` union members, its `CANVAS_TOOLS` row, and any `canAddTo` / `strokeReaches` rules in `editor/canvas/canvasTool.ts`; update `strokeIntent` (`useToolStroke.ts`), `outlinedLayerFor`, and `inputRules` (`canvas/canvasInput.ts`) if its gesture or outline differs; create `editor/canvas/strokes/<kind>.tsx` (`StrokeKindModule`) and register it in `SceneLayer.tsx`; and handle its completed stroke in the tool's `finishStroke`.
- **Add a layer type:** create a folder in `editor/layers/<type>/` for its type, factory, saved-file check, edits, and view; add it to the `Layer` union in `editor/layers/layer.ts`; and fix every compile error (`assertNever` flags every site that branches on layer type).

Platform differences live in `.web.ts` files next to their native versions
(`saveImage.web.ts` downloads instead of saving to Photos;
`projectStorage.web.ts` keeps projects in IndexedDB, since `expo-file-system`
has no web implementation; `showAlert.web.tsx` draws its own dialog because
React Native Web's `Alert` does nothing).

## Editor Layouts

Phones keep the dock and its trays. A wide window (1024 points and up, web and
iPad) puts the tools in the rail and the open tool's options in the header's
context bar (`shell/ContextBar`), with the layers in the inspector; DESIGN.md
gives the sizes, and the shorter-window and fine-pointer variants.

- `editorChrome.ts` builds the toolbar's buttons from the specs and the editor's own entry, Add photo (`toolbarEntries`, with `TOOLS` and `TOOL_KEYS` holding only that), and a selected layer's actions: the tools whose spec acts on it, in the toolbar's order (`layerActionsFor`), followed by the buttons tools add for it (a definition's `layerAction`, like Save as sticker). The list of shortcuts takes its tool lines from the same buttons (`shortcutGroups`).
- `modeChrome` (`editorChrome.ts`) chooses the panel, its title, and what ✕ and ✓ do (a tool has ✕ only when its spec `cancels`), once for both layouts, and whether the panel sits in the bar (on a wide window, every panel but `"idle"`). The bar's ✕ and ✓ are `ModeActions` in `shell/modeActions.tsx`, shared with the dock's footer, which only draws them.
- What each panel shows comes from the definition (its `views`) of the open tool, or of the tool that styles or edits the selected layer (`stylesLayer` / `edit`), or else, for a selected layer, its actions from `PanelViews.tsx`. A tool's title and actions stay in `editorChrome.ts`. So the two layouts can't disagree about which panel shows, what it does, or which tools they offer.
- A tool's `Stage` (Crop's canvas) is drawn opaque over the canvas inside the stage, clear of the rail, the inspector, and the dock (`ToolStage` in `PanelViews.tsx`), with its `Controls` strip under it: above the dock on a phone, along the stage's bottom on a wide window. A tool's `Sheet` (Stickers') is a bottom sheet on a phone and a popover beside its rail button on a wide window (`ToolSheet`); the rail gives each such tool's button an anchor.
- A tool's `Card` (Find's Faces, Text, and Both over its results; Adjust's four adjustments over its dial) is a floating card along a wide canvas's bottom, centered between the rail and the inspector (`ToolCard` in `PanelViews.tsx`). Its choices sit in the card with what they change, since the bar's far corner didn't read as part of them; the bar keeps what's set once, like Find's redaction style. The card is `CARD_HEIGHT` at least, and the canvas leaves a constant `CARD_INSET` for it as the tool opens (`useEditorLayout`'s `cardOpen`), so the photo holds still while Find's status or Adjust's value changes. It's measured by no `onLayout`: a height reported back after the tool opens is a second change to the canvas's frame (see docs/GOTCHAS.md). It has no backdrop, so taps and drags on the canvas still reach Find's regions and Adjust's dial.
- `optionsOpen` (the context's `trayOpen`) is only the phone's tray; the wide layout never reads it. A popover's open state belongs to its chip.
- The layers inspector holds only the layers. It stays open when the window is at least 960 points tall (`editorFrame`), and opens for Layers on a shorter one.
- A fine pointer gets controls sized for a mouse (`compactControls` from `ui/density.ts`). It's read once as the page loads, like the palette, so each size is a constant chosen when its module loads (`HEADER_HEIGHT`, `PANEL_GAP`, `RAIL_WIDTH`).

### The context bar

A tool returns its options as `BarGroup`s and the bar (`BarSections`) inserts
the rules between them: `Children.toArray` doesn't enter a component, so the
bar can't find groups inside one. A fragment is one child of a group, so the
buttons inside it stack in that slot. The row scrolls, and its fade covers
from the first option that doesn't fit whole (`ui/FadeRow.tsx`, its geometry in `ui/rowFade.ts`); `onLayout` x is
relative to the parent, not the scrolled viewport, and a chip's popover sits
outside that measurement parent so its choices don't count as options.

### Popovers

`ui/Popover` is modal on web and on native. `placement` is `below` (under the
control, or above it near the window's bottom) or `beside` (at the control's
right, top-aligned, for a button in the rail). On web it portals to
`document.body`, sits under tooltips and alerts, and stops Escape in the
window's capture phase, so the editor doesn't also finish the tool.

While a tool that types is open (its spec's `takesKeys` is `"typing"`, as
Text's is), a press in the context bar or dock would blur its hidden input: both
prevent that mousedown's default on web (`keepFocus`), as the canvas does,
and the popover's `restoreFocus` returns the caret to the input.

## Rendering

- **Straight onto the canvas.** The editor and export draw each document layer straight onto the canvas, never inside a saved layer: a Skia backdrop filter reads only the layer it's drawn in (so redactions blur the photo), and a highlighter's multiply blends onto whatever is beneath.
- **Redactions.** The declarative API can't draw into a backdrop layer, so `RedactionLayerView` records an `SkPicture` that calls `saveLayer` with a backdrop itself. Pixelation is built from blur, displacement map, shader, offset, and morphology filters (`pixelateFilter`), since Skia's web build has no runtime-shader or picture image filters.
- **Highlighter.** A highlighter stroke starts a drawing whose `blend` is `"multiply"` (`strokeBlend` in `editor/layers/drawing/drawing.ts`). `drawStroke` joins the mark it's given only when the stroke blends the same way, so a pen or the see-through marker (`tip: "ink"`, drawn at `MARKER_OPACITY`) stays on its own layer. `DrawingLayerView` sets the blend on the group's paint and draws the strokes at full strength, so strokes in one layer composite normally and the group multiplies once: two highlights darken where they cross only when each is its own layer. A marker saved before the field has no `blend` and still draws at `MARKER_OPACITY`. Multiply vanishes on a near-black canvas and turns white text the highlight color there, which is why the see-through marker remains. On web, multiply was checked over white (`#FFD60A` stays 255, 214, 10, black text under it stays black), over a second highlight (`#FFB400`), and over a blue sticker (dark olive); the export preview matched by day and at night.
- **A drawing's saved layer.** Only a drawing that needs one gets it (`needsOwnLayer`: it multiplies or holds an eraser stroke, or is dimmed, or a live stroke joins it); plain ink draws the same straight onto the canvas. That layer is clipped to the drawing's ink (`inkRect`), with the clip on a group outside it, so it costs the drawing's size rather than the canvas's, and the live eraser joins a drawing only once its line comes near it (`nearDrawings`). Marks make a page of handwriting into a hundred or more drawings, and unbounded, 50 of them fell to 11 fps on web ([#88](https://github.com/nverkhachoyan/tuck/pull/88)); a phone has yet to confirm 200 ([#95](https://github.com/nverkhachoyan/tuck/issues/95)).
- **Color space.** Skia works filters and color matrices in the surface's color space. On iOS a `Canvas` defaults to Display P3, while offscreen renders (export, thumbnails, the eyedropper) and the web are sRGB, so the editor's and crop tool's canvases set `colorSpace="srgb"`; any canvas that previews the document should too.
- **Decoded images.** Image layers load through `decodeImage` and the shared `decodedImages` cache (`editor/render/decodedImages.ts`), so the editor and export hold one copy of each image and a failed read or decode rejects instead of resolving to `null`. A holder releases an image and forgets it in the same cleanup. `useDecodedImage` keeps showing its image until the next has decoded, and releases it only in the step that swaps its state. Anything that keeps an image past its holder (a recorded `SkPicture` keeps its pixels) is cached by the decoded image, as `maskedRedactionPicture` is. The cache waits two animation frames before freeing, since on web a Skia canvas can still replay the scene recorded before React let go of an image. What draws offscreen takes image layers' photos from `offscreenPhotos`, which is that cache on native and, on web, a cache of its own that decodes with the browser, outside CanvasKit's heap, so export there doesn't share the editor's copy.
- **Offscreen.** `editor/render/drawOffscreen.ts` is `drawAsImage` on native and one shared surface on web, freed with its WebGL context once idle: Skia's own offscreen surfaces there share a context that lives as long as the page, and `drawAsImage` leaves each surface to garbage collection. The export sheet shows its render as a small PNG data URL in a React Native `Image`, not the render's `SkImage`, which quick size changes disposed while Skia still drew it.
- **Text** is edited in place: the canvas draws the draft layer, its caret, and its selection with Skia, and a `HiddenTextInput` takes the keyboard, out of sight behind the header. A visible input can't match: React Native lays out text differently from a Skia paragraph, and can't draw the outline, per-line boxes, or a stretched layer. Caret geometry comes from `@tuck/skia-text-input/core` (`packages/skia-text-input/`), which `editor/layers/text/textLayerLayout.ts` gives the text layer's paragraph.
- **Worklets.** Geometry gestures need on the UI thread is marked `"worklet"`, in the plain files as well (`document/geometry.ts`, `layers/strokes.ts`'s hit testing, `layers/shape/shape.ts`'s line checks), `editor/layers/layerTransform.ts`, and the editor's `canvas/`, crop, layer reorder, and dial modules. The directive is just a string, so those files stay free of React Native.

## Web

The web app is a static export hosted on Vercel at tuck.tools.

- **Entry.** Skia's module binds to CanvasKit the moment it's first evaluated, and Expo Router evaluates every route at startup, so `index.web.ts` loads CanvasKit and only then dynamically imports `expo-router/entry`. It imports `expo` first, because Expo's runtime installs the loader Metro's dynamic `import()` needs.
- **No hydration.** `index.web.ts` sets `__EXPO_ROUTER_HYDRATE__` to false, so the browser renders each page afresh. The server's HTML can't match the client's: it's in the day palette, and the server has no icon font. The prerendered HTML is only a placeholder until the bundle and CanvasKit load. `+html.tsx` applies a chosen palette to the page before the app loads.
- **Hosting.** Vercel only serves files: `vercel.json` sets the pnpm install and build commands over the dashboard's (npm can't install `workspace:*` dependencies), turns on `cleanUrls` (`/create` → `create.html`) and rewrites each dynamic route to the page Expo exports for it, named without `.html` (`/projects/:id` → `/projects/[id]`). A new dynamic route needs a rewrite there, and a moved route a redirect there: Expo Router's `redirects` option doesn't run in a static export's client. Vercel answers an unknown path with `404.html`, which `build:web` copies from Expo's `+not-found.html`.
- **Routes.** A project's routes can be the first screen, from a link, a reload, or Back and Forward. The editor opens its project itself with `useProjectSession`; export sends the user to the editor to do that. Export is a `containedTransparentModal` sheet (`src/app/_layout.tsx`), so the editor stays mounted behind it, unfocused, with its keyboard shortcuts off. `unstable_settings.anchor` isn't used to put home underneath, because Expo Router hands the anchor the link's params (going back shows `/?id=…`). The editor's Back replaces the route with home when there's nothing behind it.
- **Content Security Policy.** `vercel.json` allows only the site itself, plus `blob:`, `data:`, and `'wasm-unsafe-eval'`. Anything new the app loads or connects to, or a new inline script, needs it changed; `pnpm build:web` fails when an inline script's hash is missing from `script-src` (`scripts/check-csp.mjs`). `connect-src 'self'` also keeps MediaPipe from sending its usage logs to `odml.pa.googleapis.com`, which it does unconditionally.
- **Service worker.** `build:web` writes `dist/sw.js` from `scripts/service-worker.js` (`scripts/write-service-worker.mjs` adds the version, a hash of the precached files, and the list). It precaches the pages, scripts, fonts, icons, and CanvasKit; keeps the detection engines with the version that first used them and stickers from their first use; and serves pages from the network while online. A new version waits until home's "A new version of Tuck is ready" Reload, or every tab closes. Each version's cache holds unhashed files too, so lookups check `CURRENT` before other versions (`caches.match` alone returns the oldest copy). `index.web.ts` registers it only in a production build. Removing it means deploying a `sw.js` that unregisters itself on activate: deleting the file leaves installed workers running.
- **Shared photos.** Photos shared to the installed app (the manifest's `share_target`) are posted to the service worker, which keeps them in the `tuck-shared` cache and redirects to home's `shared` param; ones opened with it (`file_handlers`) arrive through `window.launchQueue` and are kept there too (`photos/sharedPhoto.web.ts`).

## Native

- Native configuration lives in `app.json` and config plugins, since `ios/` and `android/` are generated by `expo prebuild` (see [development.md](./development.md)).
- iOS 27 stops an app built with its SDK at launch (`EXC_BREAKPOINT` in `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`) unless it adopts the scene life cycle. Expo 58's template does: its `SceneDelegate.swift` creates the window and starts React Native once a scene connects.
- The app runs on iPad (`ios.supportsTablet`). An iPad app must allow every orientation and a resizable window, so Expo writes all four orientations to `UISupportedInterfaceOrientations~ipad` while the iPhone stays portrait.
- **Shared photos** come in through `modules/share-target`: an iOS share extension (a target its config plugin adds to the Xcode project) and an Android `ShareActivity`. Both copy the photo where the app can read it (the App Group `group.<bundle id>` on iOS, which Expo autolinking reads from the entitlements and `expo-file-system` can open; the cache on Android, since the content URI's grant belongs to the share activity) and open `<scheme>://share?file=<name>`. `src/app/+native-intent.ts` turns that into home's `shared` param. A link that arrives while the app runs goes through `router.dismissTo`, since a plain navigate pushes a second home over the editor.
