# Development

How to build, run, and test the app on each platform, and the quirks of the
tools used to check a change. [README.md](../README.md) has the short version;
[architecture.md](./architecture.md) describes the code.

## Native builds

The app runs in a development build (`expo-dev-client`), not Expo Go, which
lacks the local `image-analysis` module and fails at startup. `ios/` and
`android/` are generated by `expo prebuild` and ignored by git. Rebuild with
`npx expo run:ios` or `npx expo run:android` after changing `modules/`,
`app.json`, or a native dependency (run `npx expo prebuild --clean` first when
`app.json` or a plugin changed). JavaScript changes only need Metro.

- **CocoaPods** (Homebrew Ruby 4) crashes with "Unicode Normalization not appropriate for ASCII-8BIT" unless the locale is UTF-8: run `pod install` and `npx expo run:ios` with `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`.
- **Precompiled Expo modules.** The Podfile links `ExpoModulesCore` and other modules as prebuilt xcframeworks (it sets `EXPO_USE_PRECOMPILED_MODULES`), built by one Swift compiler. A newer Xcode can reject them ("this SDK is not supported by the compiler", then "cannot find type '__ObjC::expo' in scope"), as Xcode 27.1 did Expo 57's; Expo 58's build with it. If it happens again, run `pod install` with `EXPO_USE_PRECOMPILED_MODULES=0`, and rebuild the JSI framework with `PODS_ROOT=$PWD/ios/Pods node_modules/expo-modules-jsi/apple/scripts/build-xcframework.sh --clean` (its build phase caches each slice by its sources, not the compiler).
- **Android SDK** is at `~/Library/Android/sdk` but isn't on `PATH`: export `ANDROID_HOME` to it and add its `platform-tools` and `emulator` to `PATH`. The `Medium_Phone_API_36.1` AVD runs a Google Play image, which ML Kit's Play services models need. Play services downloads those models itself, so the emulator needs a network connection once (it has been left in airplane mode: `adb shell cmd connectivity airplane-mode disable`); until then, detection rejects with "still being downloaded".

## Loading a bundle

To load a fresh bundle in the development build, `xcrun simctl terminate <udid> com.nverk.tuck`, then open `exp+tuck://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A<port>`. On Android, `adb reverse tcp:<port> tcp:<port>` first, then `adb shell am start -a android.intent.action.VIEW -d <url>`.

- Opening that URL with `simctl openurl` or the Simulator tool shows an "Open in Tuck?" prompt that must be tapped.
- `expo run:ios --no-bundler` won't take `--port` and always opens port 8081, so reopen the URL when Metro runs elsewhere.
- `CI=1 npx expo start` turns off Metro's file watching: edits never reach the app. Start the dev server without `CI` when changing code.
- A flaky `expo start --tunnel` can leave the app running a stale or half-updated bundle with no error. If behavior contradicts the code, check Metro's output for "Tunnel connection has been closed", and prefer LAN mode (`npx expo start`).

## Devices

- **iOS 27** stops an app built with its SDK at launch unless it adopts the scene life cycle, which Expo 58's template does (see architecture.md). The simulators run iOS 26.5, so only a device shows it. Launch on a device with `xcrun devicectl device process launch --device <udid> --terminate-existing --payload-url <dev client URL> com.nverk.tuck`, and read crash reports with `xcrun devicectl device info files --domain-type systemCrashLogs`: an exit code of 0 there can still be a crash.
- **iPad** shows the wide layouts, so check a layout change on the iPad Pro 13-inch simulator too. Store screenshots come from Release builds: a development build covers the app with its floating Tools button (see [store-listing/listing.md](./store-listing/listing.md)).
- **Keyboard.** The iOS simulator here runs headless with a hardware keyboard attached, so the software keyboard never appears. Verify keyboard layout on a real device.

## The iOS Simulator tool

- Taps can silently go nowhere after repeated terminate and reload cycles: the JS thread hangs while the simulator stays responsive. Press the hardware HOME button; if that works but in-app taps don't, `simctl terminate` and relaunch.
- `text` returns before the app has handled the keystrokes, so a tap right after it can act on an empty input. Screenshot to confirm the text landed first.
- `screenshot` can return a frame from before the last tap or gesture took effect. Take a second one before deciding a tap did nothing.
- Taps sent back to back can land about 10ms apart, and React Native then never sees the second. Before calling a lost tap a bug, check how far apart the contacts were with `xcrun simctl spawn booted log show --predicate 'eventMessage CONTAINS "presence: touching"'`, and space taps out with a screenshot between them.
- To check which color space a filter ran in, read a neutral gray from `xcrun simctl io booted screenshot` (sRGB-tagged): grays have the same values in sRGB and P3, so only the filter's own math moves them.

## The browser pane and headless Chrome

- While the Browser pane is hidden, its page runs about two animation frames a second. Anything timed against drawing can fail there and nowhere else, and WebGPU work can stall entirely. Check timing-sensitive behavior and time GPU inference in headless Chrome over CDP, which runs at 60 frames a second and finds the Mac's Metal adapter.
- In headless Chrome, `--window-size` without a display leaves the viewport 1 pixel tall unless `Target.createTarget` is called with `newWindow: true` and explicit dimensions.
- **Dragging a gesture.** Use the `computer` tool's `left_click_drag`: synthetic `PointerEvent`s throw from RNGH's `setPointerCapture`. It sends a single move, and a Pan counts translation from where it activates, so a Pan with an `activeOffset` sees none; drive those with several `Input.dispatchMouseEvent` moves over CDP.
- **The photo picker.** `expo-image-picker` appends its `<input type=file>` and clicks it in one synchronous step, so patching `input.click()` or a `MutationObserver` is too late. Listen on `window` in the capture phase: on the input's `click`, `preventDefault`, set `files`, and dispatch `change` from a `setTimeout`. Stop the input's `cancel` from propagating, or the picker's handler runs twice and throws a `removeChild` error.

## Checking a web export

The `web-export` launch configuration serves `dist/` with `serve` (clean URLs, like Vercel) to check `npm run build:web`. `serve` doesn't apply `vercel.json`'s rewrites or headers. To check them, write `dist/serve.json` before starting it (`serve` reads it only at startup): `{"headers": [{"source": "**", "headers": [...]}]}`, plus `"rewrites"` for `/projects/:id` (to `/projects/[id].html`) and its `/export` for the service worker's precache.

The service worker it installs stays registered for that origin, so a dev server later started on the same port (the `web` configuration moves to 8083 when 8082 is taken) is served the old export. If the page shows code you've changed, check `navigator.serviceWorker.controller`, then unregister it and delete its caches.

Vercel previews sit behind a login, so check routing locally: `npx vercel build`, with a `.vercel/project.json` giving `"framework": null`, `"outputDirectory": "dist"`, and `"buildCommand": "npm run build:web"`, writes the routes Vercel will follow to `.vercel/output/config.json`, with each page's served path under `overrides`.

## Testing shared photos

- **Web share target.** Neither a share nor a file launch can be set off from a page. Test a share by submitting a multipart form to `/share-target` from `about:blank` in headless Chrome over CDP (the app's CSP has `form-action 'none'`, and a `fetch` POST follows the redirect, hiding it). Test a launch by wrapping `LaunchQueue.prototype.setConsumer` with `Page.addScriptToEvaluateOnNewDocument` to hand the consumer a real file handle from `navigator.storage.getDirectory()`. CDP's `Page.getAppManifest` leaves `file_handlers` out even of a valid manifest; only its `errors` mention them.
- **iOS simulator.** `xcrun simctl addmedia` a photo and share it from Photos, or put a file in `shared-photos/` under `xcrun simctl get_app_container <udid> com.nverk.tuck group.com.nverk.tuck` and `simctl openurl` the link. A cold start in the development build stops at the dev launcher, which passes the link on once a server is picked. Fast Refresh re-runs `redirectSystemPath` with the last link and doesn't reliably apply its result, so judge cold starts only after a real terminate.
- **Android.** `am start -a android.intent.action.SEND -t image/jpeg --eu android.intent.extra.STREAM content://media/external/images/media/<id> --grant-read-uri-permission` opens the system chooser.
